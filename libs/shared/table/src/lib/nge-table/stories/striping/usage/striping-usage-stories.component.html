NgeTable — Zebra Striping (Usage)

One flag, one token, and no state. Striping is a display concern: it derives from the row's position in the processed row model on every render, is never persisted, and never touches the datum. No example below imports @tanstack/*.

1. Switching it on

enableStriping is the whole API. Alternate rows take --nge-table-row-surface-alt; the rest keep --nge-table-row-surface, which is transparent by default so a row shows the table surface through it. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  enableStriping: true,
  getRowId: row => row.id,
{{ "}" }});

2. The default is off

Omit the flag and nothing about the rendering changes — the same table as before the feature existed. Striping is a strong default to impose on a table that may already be carrying marks of its own, so it is opt-in. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  getRowId: row => row.id,
{{ "}" }});
// enableStriping defaults to false

3. Where the parity comes from

Nothing to configure here, but worth knowing, because it is what makes the two cases below work. Parity is the row's index in the processed row model — the same model the virtual window is cut from, after filtering and sorting. It reaches the DOM as a nge-table__row--alt class.

The two positions that are not used are the interesting ones. :nth-child would read the DOM, which under virtualization holds a recycled window, so the stripes would crawl as you scrolled. The engine's row.index is the position in config.data and survives a sort unchanged, so the stripes would scramble the first time a column was sorted. 

// Not something a consumer writes — this is what the library does with it.
<div class="nge-table__row nge-table__row--alt">…</div>

.nge-table__row--alt {{ "{" }}
  --nge-table-internal-row-surface: var(--nge-table-row-surface-alt, #fafafa);
{{ "}" }}

4. With virtualization

Compose the two flags and nothing else is needed. Parity is computed for the windowed rows from the same model position, so a stripe stays with its row across a scroll of ten thousand rows. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,              // 10,000
  enableStriping: true,
  enableVirtualization: true,
  getRowId: row => row.id,
{{ "}" }});

5. With pinned columns

Also nothing to do. The pinned lanes read the row's resolved surface by inheritance, so a striped row is one continuous band rather than three. Scroll sideways to check the seams. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  enablePinning: true,
  enableStriping: true,
  getRowId: row => row.id,
{{ "}" }});

state = createNgeTableState({{ "{" }}
  columnPinning: {{ "{" }} left: ["name"], right: ["owner"] {{ "}" }},
{{ "}" }});

6. Under a mark

A stripe always loses. It never declares background — it swaps the value the row's background already resolves through — so hover, selection, cell ranges, column selection, highlighting and the fill region all read on an alternate row exactly as they do on a plain one. Two rows are selected below, one striped and one not. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  enableRowSelection: true,
  enableStriping: true,
  getRowId: row => row.id,
{{ "}" }});

7. Theming the alternate surface

One token, and all ten domain themes bridge it onto their own surface-container-low tier. A consumer overriding it writes the same thing from a wrapper class — the Theming story demonstrates it. 

.my-table-theme {{ "{" }}
  --nge-table-row-surface-alt: #f4f6fb;
{{ "}" }}
