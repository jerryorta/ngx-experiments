NgeTable — Theming Examples

The table has no config.theme. Everything visual is a --nge-table-* CSS custom property, so theming is a scoped selector that re-declares the properties — which is exactly what every section below is. The defaults are literal light-mode values in src/lib/styles/_table-tokens.scss, which is why the library renders correctly with no theme imported at all.

1. Default — no overrides

Nothing is set here. This is the contract's own fallback layer, and the reason a consumer can drop <nge-table> into an unthemed page and get a readable table.

2. Surfaces & content

The viewport, the header/footer band, the row backgrounds and the text on them. Hover a row to see --nge-table-row-surface-hover. 

.my-table-theme {{ "{" }}
  --nge-table-surface: #fdf8f3;
  --nge-table-surface-variant: #f0e4d7;
  --nge-table-row-surface-hover: #f7ede2;
  --nge-table-on-surface: #3d2c1e;
  --nge-table-on-surface-variant: #8a7360;
  --nge-table-header-on-surface: #6b4423;
{{ "}" }}

3. Borders

Row and column separators share --nge-table-border-color; --nge-table-header-border-color is separate because the rule under the header band usually wants to be stronger than a row separator. 

.my-table-theme {{ "{" }}
  --nge-table-border-color: #c8d6e5;
  --nge-table-border-width: 2px;
  --nge-table-header-border-color: #2e86de;
{{ "}" }}

4. Density

Row height, header height and cell padding — two boxes, one config. But the two height tokens are only reachable from CSS when the config leaves them out, and that is the sharpest edge in the whole contract, so it is worth being exact about.

createNgeTableConfig() fills in rowHeight and headerHeight from NGE_TABLE_DEFAULTS unconditionally, and <nge-table> then publishes both as inline custom properties on its host element — where they beat a wrapper class outright, because an inline declaration outranks a class selector regardless of specificity. So the tables below are the one place in this story whose config is hand-authored rather than built by the factory: a config that omits the fields makes the component remove the properties, which is exactly how the tokens get handed back to the theme.

Cell padding has no such caveat — it is never written inline, so it themes from CSS either way. And when virtualization is on, rowHeight must come from the config no matter what: the virtualizer positions rows it has not rendered yet, so it needs the number in TypeScript and pins the token to it. 

// Hand-authored — no rowHeight / headerHeight, so CSS owns them.
config: NgeTableConfig<Row> = {{ "{" }} columns, data, getRowId {{ "}" }};

.compact {{ "{" }}
  --nge-table-row-height: 28px;
  --nge-table-header-height: 32px;
  --nge-table-cell-padding-x: 8px;
{{ "}" }}

.roomy {{ "{" }}
  --nge-table-row-height: 60px;
  --nge-table-header-height: 64px;
  --nge-table-cell-padding-x: 20px;
{{ "}" }}

5. Typography

--nge-table-font-family defaults to inherit, so a table adopts the page's face unless it is told otherwise. Header size and weight are separate tokens from the body's. 

.my-table-theme {{ "{" }}
  --nge-table-font-family: ui-monospace, "SF Mono", Menlo, monospace;
  --nge-table-font-size: 12px;
  --nge-table-line-height: 18px;
  --nge-table-header-font-size: 11px;
  --nge-table-header-font-weight: 700;
{{ "}" }}

6. Pinning

Scroll this table sideways. A pinned lane is position: sticky and passes over the centre lane, so its surface token must stay opaque — a transparent one lets the scrolling cells bleed through underneath. The two shadow tokens mirror each other: the left lane casts rightward, the right lane leftward. 

.my-table-theme {{ "{" }}
  --nge-table-pinned-surface: #eef7ee;
  --nge-table-pinned-surface-hover: #dcefdc;
  --nge-table-pinned-header-surface: #d6ead6;
  --nge-table-pinned-left-shadow: 4px 0 8px rgb(27 94 32 / 0.28);
  --nge-table-pinned-right-shadow: -4px 0 8px rgb(27 94 32 / 0.28);
{{ "}" }}

--nge-table-pinned-left-sticky-offset and its right-hand twin move where a lane anchors inside the viewport. Zero is correct for a plain table; they exist so an app with a permanent gutter at an edge can shift the anchor without patching the library. --nge-table-pinned-z-index and --nge-table-header-z-index are deliberately low and explicit so an app can lift its own overlays over the table without fighting a magic number — the header must outrank the lanes, because at the top-left corner cell the two stickies cross and the header has to win.

7. Interaction — resize grip & focus ring

Hover a header's trailing edge, then drag it; then tab into a header. The grip is transparent at rest on purpose — a permanent rule between every pair of columns is noise, and the affordance is the cursor — so these tokens are only visible under the gestures that summon them. 

.my-table-theme {{ "{" }}
  --nge-table-resize-handle-width: 8px;
  --nge-table-resize-handle-color: transparent;
  --nge-table-resize-handle-color-hover: #f0a202;
  --nge-table-resize-handle-color-active: #d94f04;
  --nge-table-focus-ring-color: #d94f04;
  --nge-table-focus-ring-width: 3px;
{{ "}" }}

8. Slot chrome

The bands a [ngeTableSlot] template renders into. Only the chrome is tokenised — what a slot renders is the consumer's markup carrying the consumer's own styles, and a token that tried to style it would be dictating rather than theming. 

.my-table-theme {{ "{" }}
  --nge-table-toolbar-padding: 16px 20px;
  --nge-table-row-detail-surface: #ede7f6;
{{ "}" }}

--nge-table-loading-scrim is translucent by default, because a refresh over existing rows should read as “these are going stale”, not as an empty table. Its z-index outranks the header's: an overlay the sticky header punched a hole through would be a worse lie than no overlay at all. 9. Dark

The whole contract restated for a dark surface — the shape a domain's --nge-table-* bridge will take when the first consumer adopts the library. Note that the pinned surfaces have to be restated too and cannot fall back to the light values: they are opaque by requirement, so a missed one shows up as two pale rectangles punched through a dark table.

11. What a wrapper class cannot change

Not every name in _table-tokens.scss is a knob a wrapper class can turn. Four tiers exist, and only the first two are demonstrable above; setting a token from the rest does nothing, so this story does not pretend otherwise.

  • Read from CSS — everything in sections 2–9. A wrapper class changes them. --nge-table-row-surface-selected and --nge-table-row-surface-alt belong in this tier too; the features that read them are simply switched off here, so the Selection and Striping theming stories are where they are demonstrated.
  • Overwritten inline by the component — --nge-table-row-height and --nge-table-header-height, whenever the config carries a value for them. createNgeTableConfig() always does, and virtualization always does; only a hand-authored config that omits the fields leaves them to CSS. See section 4.
  • Mirrored in TypeScript, not read from CSS — --nge-table-column-min-width, --nge-table-column-default-width and --nge-table-column-max-width. The resize drag clamps against NGE_TABLE_DEFAULTS, because it cannot measure a column it has not rendered. The knob that works is NgeTableConfig (columnMinWidth / columnDefaultWidth / columnMaxWidth), or minSize / maxSize per column.
  • Never yours to set — the --nge-table-internal-* family. <nge-table> writes live lane geometry onto its own host element on every state change; overriding one breaks layout rather than restyling it, which is why it is deliberately absent from the token partial.
