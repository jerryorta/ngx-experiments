NgeTable — Usage Examples

<nge-table> takes one required input: a NgeTableConfig. Every example below draws its rows from the shared fixture (@nge/table/testing) rather than an inline array — and note that no example imports @tanstack/*. That insulation is the point of the facade.

1. Basic Usage

Columns and rows are the only required fields. Click a header to sort — sorting is on by default, and the table keeps its own copy of the state when the host does not bind one. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: createNgeTableFixture({{ "{" }} rows: 25 {{ "}" }}),
{{ "}" }});

<nge-table [config]="config" />

2. Custom Geometry

rowHeight and headerHeight are applied as inline --nge-table-* overrides. They live in the config rather than in CSS alone because virtualization (ARCH-245) needs them as numbers — it positions rows it has not rendered yet and so cannot measure one. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns, data,
  headerHeight: 56,
  rowHeight: 64,
{{ "}" }});

3. Sorting Off

With enableSorting: false the headers lose their affordance, their aria-sort, and their keyboard focus stop. Capability flags gate the whole interaction, not just the visual. 

config = createNgeTableConfig<Row>({{ "{" }} columns, data, enableSorting: false {{
            "}"
          }});

4. Stable Row Identity

Supply getRowId whenever selection, expansion, or sizing state outlives the data. Without it the engine keys row state by array index, so a re-fetch that reorders rows silently moves the user's selection onto different records. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns, data,
  getRowId: row => row.id,
{{ "}" }});

5. Empty State

No rows renders the header plus an empty band rather than a bare header rule, so an empty result never reads as a broken table.

6. Three Pinned-Left Columns

Scroll sideways. All three frozen columns hold their place and none of them overlaps — because they are not individually sticky. They are ordinary flex children of one sticky lane wrapper, so there is no per-cell left for a second frozen column to collide with. The component this library replaces did it per-cell, and its own source says so: "only one sticky column is supported; multiple sticky columns will overlap because they all use left: 0". 

config = createNgeTableConfig<Row>({{ "{" }} columns, data, enablePinning: true {{ "}" }});

// WHICH columns are frozen is state, not config — a user changes it.
state = createNgeTableState({{ "{" }}
  columnPinning: {{ "{" }} left: ['name', 'status', 'quantity'] {{ "}" }},
{{ "}" }});

<nge-table [config]="config" [state]="state" />

7. Both Edges, Center Scrolling

Three lanes: pinned-left, center, pinned-right. Only the center one scrolls, and the header lanes track the body lanes exactly — not through a scroll listener, but because header and body share a single scroll viewport. Where the two stickies cross, at the top-left corner cell, the header band wins. 

state = createNgeTableState({{ "{" }}
  columnPinning: {{ "{" }} left: ['name', 'status'], right: ['amount'] {{ "}" }},
{{ "}" }});

8. Pinning Switched Off

Identical state to example 7, with enablePinning: false. The lanes collapse to one and nothing freezes. A capability flag gates the effect, not just a future affordance — the same way enableSorting: false ignores a state.sorting it was handed. The state itself is untouched, so flipping the flag back restores the frozen columns. 

config = createNgeTableConfig<Row>({{ "{" }} columns, data, enablePinning: false {{
            "}"
          }});

9. Resizable Columns

enableColumnResizing: true puts a grip on every header's trailing edge. Drag one and the width follows the pointer; columns never size themselves to their content, which is the Excel / Numbers behaviour this library was built around. Bounds come from minSize / maxSize on the column definition, falling back to columnMinWidth / columnMaxWidth on the config — here Quantity is held between 80 and 160px.

Widths land in state.columnSizing as whole numbers, already clamped, so a saved view restores exactly what the user left. Driving the drag — and the Shift + arrow keyboard path — is the Interaction story's job; this one just shows the switch. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns, data,
  enableColumnResizing: true,
  columnMinWidth: 60,   // the fallback for every column
  columnMaxWidth: 800,
{{ "}" }});

// Per-column bounds win over the config's.
{{ "{" }} accessorKey: 'quantity', id: 'quantity', minSize: 80, maxSize: 160 {{ "}" }}

10. A Custom Cell for One Column

A cell is an arbitrary Angular render target. Project an <ng-template ngeCell="…"> and that column renders your markup; every other column keeps rendering its own columnDef.cell, so adopting this is a per-column decision rather than a per-table one. Inline editing follows from the same reframing — a cell containing an <input>, not a table feature. The Interaction story drives one.

[ngeCellOf] is never read at runtime. It exists so TRow has somewhere to be inferred from, which is what makes let-cell resolve to NgeCellContext<Row> rather than NgeCellContext<unknown>. Note what the context does not contain: any @tanstack/* type. 

<nge-table [config]="config">
  <ng-template ngeCell="amount" [ngeCellOf]="rows" let-cell>
    {{ "{{" }} cell.value | currency {{ "}}" }} · {{ "{{" }} cell.row.owner.name {{ "}}" }}
  </ng-template>
</nge-table>
{{ cell.row.amount | currency }} {{ cell.row.owner.name }}

11. The Empty Slot

Everything that is not a cell is addressed by name instead of by column. The empty slot replaces the band's content, never the band itself, so an empty result still reads as a table with nothing in it. Its context reports the counts — rowCount and columnCount — because a band drawn about the table should not be handed the rows and invited to iterate them. 

<ng-template ngeTableSlot="empty" let-table>
  Nothing matched across {{ "{{" }} table.columnCount {{ "}}" }} columns.
</ng-template>
Nothing matched across {{ table.columnCount }} columns — try widening the search.

12. Toolbar and Footer Bands

toolbar sits above the scroll viewport, so it stays put while the rows scroll under it. footer-cell is addressed per column and renders a footer row that reuses the same three lanes as the header — pin a column and its footer cell follows it into the pinned lane, with nothing in the footer code aware that pinning exists.

A slot renders; it does not calculate. The total below is computed by the host and handed in, which is what keeps the table from growing an aggregation feature by accident. 

<ng-template ngeTableSlot="toolbar" let-table>…</ng-template>
<ng-template ngeTableSlot="footer-cell" ngeTableSlotColumn="amount">…</ng-template>
Orders {{ table.rowCount }} rows · {{ table.columnCount }} columns Total {{ bandedTotal | currency }} Showing all {{ table.rowCount }} orders · the total is computed by the host

13. Exporting what the table shows

readNgeExportData() reads the table as a neutral shape — the active sort, filters, column order, and visibility already applied. It is a pure read and knows no output format, so a CSV or XLSX writer is an addon over the shape rather than a feature of the table. Drive it in the Interaction story; this is the API. 

<nge-table #table [config]="config" [(state)]="tableState" />

private readonly table = viewChild.required<NgeTableComponent<Row>>('table');

const data = this.table().readNgeExportData();
// data.columns → { id: 'amount', header: 'Amount' }[]
// data.rows    → { id: 'row-0001', cells: [{ columnId, raw, formatted }, …] }[]

// Which rows: every processed row, the rendered page, or the selection.
this.table().readNgeExportData({ slice: 'selected' });

// Which cells: any predicate at all. This is the seam an addon plugs into —
// it is handed the same context a [ngeCell] template receives.
this.table().readNgeExportData({ cellPredicate: cell => this.isMarked(cell.rowId, cell.columnId) });

Every cell carries both readings of its value: raw for a machine (a Date stays a Date) and formatted for a person. A column says how it reads by declaring a formatter in its own namespaced meta key — the library cannot derive it, because a cell here may be a chart or an input rather than text. Keeping the two in step is the column's job. 

{
  accessorKey: 'amount',
  header: 'Amount',
  id: 'amount',
  meta: { ngeExport: { format: value => formatCurrency(value) } },
}
