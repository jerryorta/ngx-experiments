The controlled-state contract is behaviour, so it only shows up when driven. Click headers, push state in from the buttons, and watch the emitted NgeTableState below — client-side and server-side tables are indistinguishable from here, which is exactly why server-side mode later becomes a flag flip rather than a rewrite.

5. Drag to resize — Excel / Numbers behaviour

Drag any column's trailing edge. Columns never size themselves to their content — the width is whatever the user last dragged it to, which is the requirement that decided the flexbox substrate. Widths land in state.columnSizing as plain numbers, so they persist and restore with the rest of the view.

Status carries minSize: 120 and maxSize: 220, so it stops short in both directions; every other column uses the library's 60–800px defaults. Watch the JSON while you drag past a bound — the emitted value is clamped too, not just the render, so a saved view can never carry a width the table would refuse to draw.

The grip is pointer-driven (mouse, trackpad, touch and pen all take the same path), and every column is also resizable from the keyboard: focus a header and press Shift + ← / →. Double-click a grip — or press Shift + Home — to hand the column back to its defined width.

6. Resizing a pinned column

Two columns frozen left, one right, and every one of them resizable. Drag Name or Status wider and the pinned lane grows with it while the center lane reflows — no overlap at any width, and the right-hand lane stays flush to the edge.

Nothing in the resize code knows that pinning exists. Lane widths are the engine's own totals over each lane's visible columns, published as --nge-table-internal-* properties on the host, so a new width re-derives the geometry on its own. That is the pay-off for taking sticky offsets from the engine rather than computing them by hand.

8. Ten thousand rows, with columns pinned

The combination this story exists for. Name is frozen left and Owner right; scroll fast, in both directions at once, and the pinned lanes stay locked to their edges and aligned with the rows they belong to.

Windowed rows are absolutely positioned and pinned lanes are position: sticky inside them, which only works because the rows are placed with top. A transform would be the obvious way to move a row and would create a stacking context, stranding every sticky lane inside it — AG Grid hit exactly this and switched to top-positioning. Nothing here is free to "optimize" that back.

9. Resizing a pinned column, mid-scroll

All three at once — windowed rows, two lanes frozen left and one right, and every column draggable. Scroll into the middle of the dataset, then drag Name wider without scrolling back: the lane grows, the center reflows, and the rows already on screen keep their alignment.

Nothing in the virtualization code knows a column can be resized. Row offsets are arithmetic over the row height, lane widths are the engine's own totals, and the two never meet — which is why this composition needed no code of its own.

10. Inline editing — a cell containing an input

13. The event stream — one output, one union

Extension axis 4 of 4. Everything the table announces leaves through a single (ngeTableEvent), so a new kind is a member on NgeTableEvent rather than a new binding on the component. The host below does nothing but listen — no library code is involved in this panel. 

<nge-table [config]="config" (ngeTableEvent)="onEvent($event)" />

onEvent(event: NgeTableEvent<Row>) {
  switch (event.kind) {
    case 'sort-change':   return this.reload(event.sorting);
    case 'cell-click':    return this.open(event.cell.row);
    case 'column-resize': return this.save(event.columnSizing);

}
