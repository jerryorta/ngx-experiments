NgeTable — Row Selection (Usage)

Two config flags and a getRowId. The leading checkbox column is injected by the library rather than declared, so nothing changes in a consumer's column definitions. No example below imports @tanstack/*.

1. Switching selection on

enableRowSelection is off by default. Switching it on adds the checkbox column, makes rows clickable, and starts writing state.rowSelection — a plain { rowId: true } map, JSON by construction, so it persists and restores with the rest of the view. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  enableRowSelection: true,
  getRowId: row => row.id,
{{ "}" }});

state = signal(createNgeTableState());
<nge-table
  [config]="config"
  [state]="state()"
  (stateChange)="state.set($event)"
/>

2. ⚠️ getRowId is not optional here

Selection is id-keyed state. Without getRowId the engine keys it by array index, so a sort, a filter, or a re-fetch leaves the user's ticks sitting on whichever records moved into those positions — a failure that reads as data corruption rather than as a bug. Switching selection on without one throws in dev rather than degrading quietly. 

// ❌ throws in dev
createNgeTableConfig<Row>({{ "{" }} columns, data, enableRowSelection: true {{ "}" }});

// ✅
createNgeTableConfig<Row>({{ "{" }}
  columns,
  data,
  enableRowSelection: true,
  getRowId: row => row.id,
{{ "}" }});

3. One row at a time

enableMultiRowSelection: false reduces the feature to a single row: no header checkbox, no range, and both modifiers fall through to a plain replace. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns,
  data,
  enableMultiRowSelection: false,
  enableRowSelection: true,
  getRowId: row => row.id,
{{ "}" }});

4. Restoring a saved view

This table starts with three rows selected and a sort applied, because both arrived as ordinary state. That is what host-owned selection buys: a user's view — their sort, their widths, their pinned columns, and now their selection — is one JSON object to persist and hand back. State pushed in this way is deliberately silent: it emits no event, so restoring a view never reads as user activity. 

state = signal(createNgeTableState({{ "{" }}
  rowSelection: {{ "{" }} 'row-2': true, 'row-3': true, 'row-4': true {{ "}" }},
  sorting: [{{ "{" }} desc: false, id: 'name' {{ "}" }}],
{{ "}" }}));

5. Composing with pinning and resizing

The selection column is an ordinary column to everything downstream of it: it lands in a lane, takes an aria-colindex, and leads the row whether or not a host has supplied a columnOrder. It refuses sorting, resizing and hiding on its own definition, so the affordances the rest of the table offers do not appear on it. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns,
  data,
  enableColumnResizing: true,
  enablePinning: true,
  enableRowSelection: true,
  getRowId: row => row.id,
{{ "}" }});

6. Reading the selection

Two ways, for two purposes. state.rowSelection is the ids, and it is what you persist. readNgeExportData({ slice: 'selected' }) is the content, already filtered and in the current sort order — the export seam (ARCH-248), which has never heard of the selection UI. 

// the ids
const selectedIds = Object.keys(state().rowSelection);

// the content, in the order the user sees it
@ViewChild(NgeTableComponent) table!: NgeTableComponent<Row>;
const data = this.table.readNgeExportData({{ "{" }} slice: 'selected' {{ "}" }});

7. Listening for changes

One selection-change kind covers every route into the slice. A range is one event, not one per row. Selecting a row does not swallow row-click — a consumer already listening for it keeps hearing it. 

onNgeTableEvent(event: NgeTableEvent<Row>): void {{ "{" }}
  if (event.kind === 'selection-change') {{ "{" }}
    this.save(event.rowSelection);
  {{ "}" }}
{{ "}" }}

8. Selection off — the default

No checkbox column, no aria-selected, and rows are not in the tab order. A row that does nothing when activated should not be a tab stop.
