NgeTable — Row Selection (Theming)

There is no config.theme. Every section below is the same config wrapped in a different class that re-declares --nge-table-* — which is exactly what a consumer writes. The substance of this story is its SCSS; read that file alongside this page.

1. The two tokens selection reads

--nge-table-row-surface-selected tints the row and its pinned lanes; --nge-table-selection-accent tints the checkboxes through accent-color, which colours a native control rather than replacing it — so the checkbox stays keyboard-, screen-reader- and high-contrast-correct for free. 

.my-table {{ "{" }}
  --nge-table-row-surface-selected: #e3f2fd;
  --nge-table-selection-accent: #1565c0;
{{ "}" }}

3. Selected and pinned

⚠️ Scroll this table horizontally. A pinned lane is position: sticky and opaque by requirement, so it scrolls over the center lane — the selected tint has to be repainted on it or a selected row would read as selected in the middle and unselected at both edges. A theme overriding the selected surface gets that repaint automatically; a theme overriding only --nge-table-pinned-surface would break it.

4. The focus ring — only visible under a gesture

⚠️ This section shows nothing at rest. Tab into the table and note the ring on the focused row. Selection is what made rows focusable, so --nge-table-focus-ring-color and --nge-table-focus-ring-width acquired a second consumption site here (the first is the header cell, ARCH-244). This wrapper widens and reddens it so the effect is unmistakable. 

.my-table {{ "{" }}
  --nge-table-focus-ring-color: #b3261e;
  --nge-table-focus-ring-width: 3px;
{{ "}" }}

5. Dark

The shape a domain's --nge-table-* bridge will take when a consumer adopts the library. ⚠️ Every surface is restated rather than left to inherit — the pinned surfaces especially, which are opaque by requirement, so a missed one shows up as pale rectangles punched through a dark table. The selected tint has to be re-derived too: a light-mode #e3f2fd against a dark row is not a tint, it is an inversion.

6. What is and is not themeable here

Four tiers, and selection adds an entry to three of them.

  • Read from CSS — --nge-table-row-surface-selected, --nge-table-selection-accent, --nge-table-focus-ring-*. Set these from a wrapper class.
  • Mirrored in TypeScript — --nge-table-selection-column-width. The column's size is a number the engine clamps against, so the token alone would style a lane the engine still measured at the default width. Both move together, and a spec asserts it.
  • Overwritten inline by the component — --nge-table-row-height / -header-height, whenever the config carries them. createNgeTableConfig() always fills them in, and applyGeometry writes them inline on the host where they outrank any class.
  • Never yours to set — the --nge-table-internal-* family. Runtime lane geometry; overriding one breaks layout rather than restyling it.
