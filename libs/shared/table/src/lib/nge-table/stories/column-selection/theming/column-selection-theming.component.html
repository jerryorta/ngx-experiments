NgeTable — Column Selection Theming

There is no config.theme. Column selection themes through --nge-table-range-column-* custom properties, so every section below is one scoped wrapper class — the same thing a consuming app writes. Each table is seeded with a selection rather than driven, because the subject here is colour rather than gesture; drive it in the Interaction story.

1. The defaults, with nothing declared

Every token carries a literal fallback at its use site, so the addon renders correctly with no theme applied and adds nothing to _table-tokens.scss — editing that partial would be a core edit, which this feature needed none of.

⚠️ The strip is transparent at rest by design and appears on header hover. Hover a header to see it; a still screenshot of this section shows only the selected column's tint.

2. An always-visible strip

Setting the rest colour trades discoverability for quiet: the affordance no longer has to be found, at the cost of a permanent rule down every header's leading edge. Worth doing in an app whose users select columns constantly, and not in one where it is occasional. 

.always-visible {{ "{" }}
  --nge-table-range-column-handle-color: #cfd4dc;
{{ "}" }}

3. A wider target

The strip is 8px by default, inside the header's 12px padding so it never clips a label. Widening it past the padding starts to overlap the label, so this is a knob with a real ceiling rather than a free win. 

.wide-handle {{ "{" }}
  --nge-table-range-column-handle-width: 12px;
  --nge-table-range-column-handle-color: #e3e6ea;
{{ "}" }}

4. A branded accent

Four tokens carry a domain's colour: the strip when a column is selected, the header tint, the text on it, and — from ARCH-269, because the body paint is the same overlay — the cell surface and outline. 

.theme-branded {{ "{" }}
  --nge-table-range-column-handle-color-active: #7c3aed;
  --nge-table-range-column-surface: #ede9fe;
  --nge-table-range-column-on-surface: #2e1065;

  // ARCH-269's tokens paint the BODY of the same selection.
  --nge-table-range-surface: #f5f3ff;
  --nge-table-range-outline: #c4b5fd;
  --nge-table-range-on-surface: #2e1065;
{{ "}" }}

5. Dark

The shape a domain's --nge-table-* bridge will take when a consumer adopts the library. Every surface is restated rather than left to inherit — the pinned surfaces especially, which are opaque by requirement, so a missed one shows up as a pale rectangle punched through the table. 

.theme-dark {{ "{" }}
  --nge-table-surface: #1c1b1f;
  --nge-table-surface-variant: #2b2930;
  --nge-table-on-surface: #e6e1e5;
  --nge-table-header-on-surface: #e6e1e5;
  --nge-table-border-color: #49454f;
  --nge-table-pinned-surface: #2b2930;

  --nge-table-range-column-handle-color-active: #7dd3fc;
  --nge-table-range-column-surface: #0c4a6e;
  --nge-table-range-column-on-surface: #e0f2fe;
  --nge-table-range-surface: #075985;
  --nge-table-range-outline: #38bdf8;
  --nge-table-range-on-surface: #e0f2fe;
{{ "}" }}

6. A selected pinned column stays opaque

status is pinned to the left lane and selected. A pinned lane is position: sticky and scrolls over the center lane, so its header tint and its cell tint must both be opaque or the center columns show through them.

⚠️ That is a requirement on the token, not a rule in the stylesheet. No pinned-lane rule exists for this addon and adding one would be dead code — the tint is on the header cell and on the body cell, each of which paints over its own lane's background. A theme that made either translucent would be fixed on the token.

Scroll this table sideways and check nothing bleeds through.

7. The token surface

Six tokens are this feature's own; the rest of a selected column's appearance comes from ARCH-269's, because the body paint is the same overlay. 

// This feature (--nge-table-range-column-*)
--nge-table-range-column-handle-width          8px
--nge-table-range-column-handle-color          transparent   ← at rest
--nge-table-range-column-handle-color-hover    #b6b6bd       ← header hover
--nge-table-range-column-handle-color-active   #1d4ed8       ← column selected
--nge-table-range-column-surface               #dbeafe       ← header tint
--nge-table-range-column-on-surface            #0b2545

// Inherited from ARCH-269, painting the body of the same selection
--nge-table-range-surface                      #dbeafe
--nge-table-range-outline                      #93c5fd
--nge-table-range-on-surface                   #0b2545
--nge-table-range-focus-outline                #1d4ed8       ← no focus cell on a
                                                                 whole-column mark

⚠️ --nge-table-range-focus-outline is listed for completeness and does nothing for a column: a whole-column mark has no single focus cell, which falls out of the descriptor rather than being suppressed. It applies once a user shift-clicks into the body.

None of these are in _table-tokens.scss, and that is deliberate — an addon that edited the core token partial would not be an addon. Every use site carries its literal fallback instead.
