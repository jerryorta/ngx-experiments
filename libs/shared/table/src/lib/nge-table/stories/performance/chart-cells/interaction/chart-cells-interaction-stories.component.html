NgeTable — Chart Cells (Interaction)

ARCH-289 measured a plain virtualized table so a later feature's cost could be read against it. This is that feature: the same {{ counted(totalRowCount) }}-row fixture, virtualized, with one extra column whose cell renders a <nge-chart> sparkline once the scroll has been quiet long enough (cell.isSettled(), ARCH-291) — and nothing else different from the baseline's plain table. The acceptance criterion is a number, not an impression: a scripted scroll with this column present stays inside ARCH-289's frame budget, measured with the identical harness.

⚠️ This is the other half of a pair, not a replacement for the baseline story. Run Performance/Baseline/Interaction and this story back to back, on the same machine, in the same session, and compare the two there. A figure recorded on another day — or another machine — risks attributing the machine's mood to the chart column. This story also carries no hardcoded reference run of its own — see section 3.

⚠️ The row is taller here — {{ rowHeightPx }}px, not the baseline's 40px — a chart needs room the baseline's plain text cells do not. That alone changes the rows-per-step geometry, so this story's expected rowsAdded is not 714 — see section 3 for the number this story's own schedule implies.

⚠️ Only works in a real browser, and only in the foreground. A hidden tab suspends requestAnimationFrame, so the harness refuses to start — or abandons a run already in flight — rather than hang on a promise that can never settle.

  • always-shell — never a chart. The floor: what a taller row with one extra column costs before any chart exists. Optional.

⚠️ Why always-chart is not redundant. This schedule advances the viewport on every measured frame with no pause, so the scroll never goes quiet for the 150ms isSettled requires — "a fast flick shells the whole way" is the settle signal's own contract. gated therefore spends the entire run in its shell branch, and will read almost identically to always-shell. That is the gate working, but on its own it would prove "charts stay inside the budget" only in the sense that no chart was ever drawn. gated against always-chart is the comparison that carries the story's claim. A large gap demonstrates the seam; a small one is a real finding too, and worth knowing before the next expensive cell type arrives.

Run baseline → gated → always-chart, back to back in this session, two runs each. The noise floor is not a constant — p95 spread runs ~1.8% on a warm machine and 4.2–4.8% minutes after a cold rebuild — so a comparison against a figure recorded on another day risks reading the machine's state as the feature's cost.

4. What each number is for

Dropped is the one that means "it stuttered": frames past 1.5× this display's own measured frame interval, so a missed vsync rather than an assumed 60Hz. p95 sits beside worst frame because one stall is ordinary — a collection, the browser doing something else — while a p95 well above the frame interval means most frames are late, which is what a person actually perceives. There is deliberately no "frames over 16.7ms" count here either, for the same reason the baseline story dropped one: it sits on the refresh interval, so jitter relocates dozens of frames across it.

Rows built is the one to watch, exactly as in the baseline. It counts row elements the browser had to construct during the run, and a window slide pays that cost whatever the cells contain — so a chart's own cost is on top of this, never instead of it. That is what the Cell mode control isolates: always-shell shows the taller-row cost alone, gated shows whether the settle gate keeps chart-render cost off this schedule entirely (it does — this scroll never idles), and always-chart is the only one of the three that actually pays it, which is why it is the number the other two are read against.

Rows in DOM against the dataset size is the virtualization claim itself, stated as two numbers instead of a sentence — unchanged by the extra column, because a window's row count is a function of viewport height and row height, not of what a row contains.
