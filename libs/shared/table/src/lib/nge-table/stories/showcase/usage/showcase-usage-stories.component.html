NgeTable — Showcase (Usage)

NgeTableShowcaseDemoComponent is one table wearing every shipped feature — virtualization, both-edge pinning with resize, sorting and striping, row selection behind a swappable control, cell range with column selection and the fill handle, cell highlighting with CSV export, a chart cell behind the settle gate, all four inline editors, and row expansion into a chart that animates open. No example below imports @tanstack/*.

1. Adopting the composed table — 10,000 rows, virtualized

A consumer wires exactly what a caller of <nge-table> would: rows and state, two-way. The six config-gated flags below all default true, so this is the whole of it.

This one carries the full fixture — ten thousand rows — so the scroll is a real virtualization window rather than a claim about one. Only the rows near the viewport exist in the DOM; they position with top and never a transform, which is what keeps the pinned lanes sticky while you scroll. Open a row's chevron and its detail band draws two charts of that row's own series. Every section below this one runs on a small fixture instead — each teaches a single seam, and scale would only get in the way. 

<nge-table-showcase-demo
  [maxHeight]="840"
  [(rows)]="rows"
  [(state)]="state"
/>

2. Both addons are ALWAYS provided

Cell highlighting and cell range are construction-time providers, not a runtime toggle — an addon's presence cannot come and go with an @if. Only the config-gated capabilities become input() signals feeding a computed() config. 

providers: [provideNgeCellHighlighting(), provideNgeCellRange()],

In the table above, drag out a cell range and shift-click to build a highlight — both marks coexist regardless of which config flags are on, because neither addon was ever conditional.

3. One cell-overlay template, three claimants

The slot resolves to one template per column plus one shared fallback, so a second ngeTableSlot="cell-overlay" registration would silently REPLACE the first rather than compose with it. All three components that mark a cell ride the one template instead. 

<ng-template ngeTableSlot="cell-overlay" [ngeTableSlotOf]="rows()" let-cell>
  <nge-highlight-overlay [cell]="cell" [state]="tableState" />
  <nge-range-overlay [cell]="cell" [state]="tableState" />
  <nge-fill-handle [cell]="cell" [state]="tableState" />
</ng-template>

⚠️ Both overlays bind the whole state, never their own slice — a slice-bound computed has no dependency a re-sort changes, so the paint would freeze at the state it held when the marks were made.

4. The swappable selection control

The native checkbox is the default, not the only option. Projecting selection-cell / selection-header replaces it with whatever a consuming domain ships — dlc-checkbox, dlc-checkbox. The pill in the leading column above is a local stand-in, never a real design-library import: this library must never depend on one. 

<ng-template ngeTableSlot="selection-cell" [ngeTableSlotOf]="rows()" let-selection>
  <button
    [attr.aria-pressed]="selection.isSelected"
    [disabled]="!selection.canSelect"
    (click)="$event.stopPropagation(); selection.toggle($event)"
  >{{ "{" }}{{ "{" }} selection.isSelected ? '✓' : '' {{ "}" }}{{ "}" }}</button>
</ng-template>

5. The chart column's opt-outs, reused verbatim

The Trend column is exactly the shape chart-cells/usage establishes, not a second answer to the same question: enableSorting: false (ordering a number[] is meaningless), the export seam's own formatter (the default String(value) comma-joins the array), and meta.ngeFill.enabled: false — a series is a fine fill SOURCE and a meaningless fill TARGET. 

const seriesColumn: NgeTableColumn<Row> = {{ "{" }}
  accessorKey: 'series',
  enableSorting: false,
  header: 'Trend',
  id: 'series',
  meta: {{ "{" }}
    ngeExport: {{
            "{"
          }} format: value => (Array.isArray(value) ? value.length + ' points' : '') {{ "}" }},
    ngeFill: {{ "{" }} enabled: false {{ "}" }},
  {{ "}" }},
  size: 200,
{{ "}" }};

6. rowHeight: 96 is structural, not a preference

<nge-chart>'s shadow root resolves its height as a percentage of the cell, which is always definite — never auto. The library's 40px default would still render the sparkline, only squeezed into a sliver; 96px is what gives it room to actually read as a trend. It is fixed in this table's config rather than a Storybook control for exactly that reason. 

createNgeTableConfig({{ "{" }} columns, data, getRowId, rowHeight: 96 {{ "}" }});

7. Editors need no template

Status, Quantity, Amount, Active and Description each name a library editor in meta.ngeEdit; the table resolves it through the same render-slot registry a [ngeCell] template goes through, and there is nothing else to write. Click a row's status to activate the select, or its quantity/amount to activate the input; the checkbox and the textarea are one click each too. 

{{ "{" }}
  ...amountColumn,
  meta: {{ "{" }}
    ...amountColumn.meta,                          // keeps the fixture's ngeExport.format
    ngeEdit: {{ "{" }} editor: NgeCellInputComponent, editorInputs: {{ "{" }} type: 'number' {{
            "}"
          }}, enabled: true {{ "}" }},
  {{ "}" }},
{{ "}" }}

⚠️ Merging meta rather than replacing it is the whole trick above: amount already carries ngeExport.format, and a bare {{ "{" }} ...column, meta: {{ "{" }} ngeEdit {{ "}" }} {{ "}" }} would silently drop it.

8. Row expansion into a chart, animating open

Expand any row above: the band opens over --nge-table-row-detail-duration and draws a second, larger chart of the same twelve numbers. The one rule its content owes is reading the band's own height token — never align-self: stretch, which is a cell's answer and does not generalise to a block on its own line. 

.detail-band {{ "{" }}
  height: var(--nge-table-row-detail-height, 120px);
{{ "}" }}
.detail-band__plot {{ "{" }} flex: 1 1 auto; min-height: 0; {{ "}" }}

9. Exporting exactly what you marked

Mark a few cells (click to highlight, shift-click to extend), then compare the two downloads: one reads the whole table, the other reads only the cells the predicate matches. Neither the export seam nor the CSV formatter has ever heard of highlighting — they meet on the table instance alone. 

downloadHighlighted(): void {{ "{" }}
  this.download(
    this.table().readNgeExportData({{ "{" }} cellPredicate: this.highlight.predicate() {{ "}" }}),
    'nge-table-showcase-highlighted.csv'
  );
{{ "}" }}
