NgeTable — Showcase (Theming)

The same --nge-table-* contract core/theming demonstrates on the plain fixture, proved instead on the fully-loaded table: a wrapper class has to reach a pinned lane, a stripe, the selection accent, a highlight tint, a range outline, an editor panel, and a chart-bearing detail band all at once, or the comparison proves nothing.

1. Light vs dark — every surface restated

Expand a row in each table to compare the detail band's chart too. ⚠️ Every pinned surface is restated rather than inherited in the dark theme, the pinned ones especially — they are position: sticky and opaque by requirement, so one left on the light default is a pale rectangle punched through a dark table.

2. Pinning & lane tokens, forced to scroll

Eleven columns (nine of the showcase's own, plus the injected expansion and selection leads) comfortably overflow this narrowed box. Scroll horizontally: the pinned-left Name and pinned-right Created lanes stay put, their shadow and opaque surface reading as sitting above the columns sliding beneath them.

3. A brand accent — interaction tokens under a gesture

⚠️ Several of these tokens are only visible while you are doing something, and a screenshot of the table at rest proves nothing about them. Select a row to see the selection accent on the leading pill; hover a header's trailing edge for the resize grip's hover colour (it is transparent at rest by design) and drag it for the active colour; tab into a header for the focus ring.

4. Editor panel tokens

Activate the Status select or the Description textarea — both open a body-level CDK overlay, positioned outside this wrapper class entirely. The panel still picks up the theme: applyNgeEditorPanelTokens resolves NGE_EDITOR_PANEL_TOKENS through getComputedStyle at the trigger and copies them onto the pane, which is what lets a body-level panel inherit a scoped theme a plain CSS cascade could never reach on its own.

5. What a wrapper class cannot reach on THIS table

  • Read from CSS — surfaces, content, borders, the header band, pinning, typography, cell padding, the resize grip, the focus ring, slot chrome, the selected row and its accent, the alternate row, and the editor colour family. Every section above demonstrates one of these.
  • Overwritten inline, and NOT reachable here at all — --nge-table-row-height, --nge-table-header-height and --nge-table-row-detail-height. core/theming demonstrates these by hand-authoring a config that omits them; this table cannot, because rowHeight: 96 is fixed in NgeTableShowcaseDemoComponent's own config — it is what gives the series sparkline room to draw at all, so it is never a preference this composed table can hand back to a theme.
  • Mirrored in TypeScript — the column-width family and --nge-table-selection-column-width. The resize clamp and the injected columns' size read NGE_TABLE_DEFAULTS; the knob is NgeTableConfig, not a wrapper class.
  • Never a theme's business — the --nge-table-internal-* family. It carries live lane geometry the component measures for itself; setting one would break layout rather than restyle it.
