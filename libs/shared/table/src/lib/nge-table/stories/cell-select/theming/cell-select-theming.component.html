NgeTable — Cell Select Theming

The --nge-table-editor-* panel family, demonstrated the way a consumer would override it: a scoped wrapper class re-declaring tokens. There is no config.theme on NgeTableConfig — the table themes exclusively through CSS custom properties.

1. No wrapper — the literal defaults

Open a status select. The panel is white with a grey border and a soft shadow, from the :root declarations in _table-tokens.scss.

⚠️ This is the least informative section, and it is here to say why. The overlay container is a child of <body>, itself a descendant of :root — so :root defaults reach the panel by ordinary inheritance and would do so even if every mechanism below were broken. A panel that looks right with no theme loaded proves nothing about a panel under one.

2. Panel surface, border and shadow

.my-panel-theme {{ "{" }}
  --nge-table-editor-panel-surface: #fffdf5;
  --nge-table-editor-panel-border-color: #b08968;
  --nge-table-editor-panel-shadow: 0 8px 24px rgb(112 79 51 / 28%);
{{ "}" }}

⚠️ The wrapper is on the table, and the panel is not inside the wrapper. This section works only because <nge-cell-select> resolves the family off its trigger — which is inside the wrapper — and copies the values onto the overlay pane. Delete that step and the trigger would restyle while the panel stayed white. Check the panel itself, not the trigger.

3. Option states — hover and selected

.my-panel-theme {{ "{" }}
  --nge-table-editor-option-hover-surface: #e8f5e9;
  --nge-table-editor-option-selected-surface: #a5d6a7;
{{ "}" }}

Two tokens rather than one, because "where I am" and "what is set" have to stay legible at the same time. Hover down the list and note the option matching the cell's current value keeps its own tint underneath the cursor. Arrow through it as well — the keyboard cursor uses the hover token deliberately, since a user drives with one pointer or the other and two colours would claim there were two cursors.

4. Panel height cap

.my-panel-theme {{ "{" }}
  --nge-table-editor-panel-max-height: 140px;
{{ "}" }}

Twenty options against a 140px cap, so the panel scrolls internally rather than growing to fit. The flexible position strategy's resizing is deliberately off: a panel that changed height as a user arrowed through it would be harder to read than one that scrolls.

⚠️ This section swaps in a longer option list on purpose. A height cap demonstrated over four options is a section whose prose claims something the box cannot do — the same trap as a pinning section over a table that fits its panel.

5. Dark — the shape a domain bridge takes

What a domain's --nge-table-* bridge looks like when it reaches the editor family. Every surface is restated rather than left to inherit: a missed one shows up as a pale rectangle punched through a dark panel, and the panel has three of them (its own surface, the hover tint and the selected tint) where a field has one.

6. What does not reach the panel

The token tiers, for this family specifically:

  • Copied onto the pane — the whole --nge-table-editor-* family plus --nge-table-font-family and --nge-table-row-height. Themeable from a wrapper class, as sections 2–5 show, because the component resolves and forwards them.
  • Inherited from :root only — anything the component does not forward. It reaches the panel when declared globally and silently does not when scoped to a theme class. If you add a token the panel reads, add it to PANEL_TOKENS in the same change.
  • Never reaches it — <nge-table>'s inline host geometry (--nge-table-row-height and -header-height as the component publishes them) and the --nge-table-internal-* family. The first is why the resolved read happens at the trigger, which sits inside the table and therefore sees them; the second is runtime lane geometry that was never yours to set.
  • Not a token at all — the option list's contents. Options are data on the column, not styling.

⚠️ Measure the rendered panel, never the wrapper's declared token. A wrapper can declare a value the panel never receives, and devtools shows it on the wrapper either way:

getComputedStyle(document.querySelector('.nge-cell-select__panel')).backgroundColor
