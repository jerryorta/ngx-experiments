NgeTable — Cell Highlighting (Interaction)

Highlighting is an addon, not a table feature. Everything on this page is registered with one line of providers and modifies no file in the library core — which is what makes it the epic's extensibility gate (ARCH-250). Click a cell to mark it; shift-click to extend a block.

1. Click to highlight, shift-click to extend

A plain click toggles one cell and makes it the anchor. A shift-click extends from that anchor to the cell you clicked, spanning every column between them in visual order. Watch the state below: individually-picked cells are enumerated, a block is stored as a single descriptor.

2. Persist and restore

The slice is plain JSON, so a user's highlighting persists and restores with the rest of their view. Mark some cells above, save, change the marks, then restore. Pushing state back in is silent — restoring a saved view is not the user doing something, so it announces nothing on the event stream.

3. Ten thousand rows — highlighting survives a virtualized scroll

The acceptance criterion only a browser can check. Highlight a cell, scroll it far out of view, and scroll back — it is still highlighted. Virtualization recycles DOM, so the node that draws row 12 drew row 4 a moment ago; the mark survives because it lives in state and every render re-derives from there, never because an element remembered anything.

Shift-click a long way down a column and watch slice size barely move. A descriptor is one object whatever the row count — the same block enumerated per cell would be ~270 KB of JSON re-emitted on every state change, and a few such columns would exceed Firestore's 1 MiB document limit.

4. Highlighting a pinned column

name is pinned left and owner right. Highlight cells in both, then scroll sideways. A pinned lane is position: sticky and scrolls over the center lane, so a highlighted pinned cell must stay opaque — a translucent tint would show the center cells sliding underneath it.

5. A range follows the view, a picked cell follows its record

Shift-click out a block, then sort. The descriptor's endpoints are row ids, so they follow their records — but which rows lie between them is resolved against the current sort order, so the block re-shapes rather than travelling intact. Individually picked cells, being enumerated by id, stay exactly where they were put.

This is a deliberate reading of "the block the user dragged out", and it is the one AG Grid's coordinate-based ranges get wrong in the other direction — theirs survive a scroll but not a sort. ARCH-269 and ARCH-270 inherit this decision.

6. Exporting only the highlighted cells

Two independent addons composing without importing each other. The export seam takes a cellPredicate and has never heard of highlighting; the highlight addon supplies one and has never heard of exporting. They meet on the table instance and nowhere else — which is exactly what ARCH-251's CSV formatter will build on.
