NgeTable — Cell Highlighting (Usage)

Cell highlighting is an addon over <nge-table>: a TableFeature for the state, the existing cell-overlay slot for the paint, and a predicate for export composition. It touches no file in the library core, which is what makes it the epic's extensibility gate.

1. Switch it on

One entry in providers. It registers the feature, the view bridge the overlay resolves, and the hand-off between them. Put it on the component that hosts the table, never in root providers — highlighting is per-table. 

@Component({{ "{" }}
  providers: [provideNgeCellHighlighting()],
  …
{{ "}" }})

2. Project the overlay

One template covers every column: the slot registry falls back to a shared registration when a column has none of its own. The overlay renders nothing — it carries a class, and the addon's stylesheet paints the cell around it. 

<nge-table [config]="config" [(state)]="state">
  <ng-template ngeTableSlot="cell-overlay" [ngeTableSlotOf]="rows" let-cell>
    <nge-highlight-overlay [cell]="cell" [highlight]="state().ngeHighlight" />
  </ng-template>
</nge-table>

3. Mark a cell

The cell-click event carries a NgeCellContext — ids and values, no @tanstack/* type — and the bridge takes the same ids. Click any cell below. 

private readonly highlight = inject(NgeHighlightBridge);

onEvent(event: NgeTableEvent<Row>): void {{ "{" }}
  if (event.kind === 'cell-click') {{ "{" }}
    this.highlight.toggle(event.cell.rowId, event.cell.columnId);
  {{ "}" }}
{{ "}" }}
state.ngeHighlight
{{ stateJson() }}

4. getRowId is mandatory

Every mark is keyed by getRowId(row). Without one the engine keys rows by array index, so a sort, a filter, or a re-fetch silently moves the user's highlights onto different records — the failure that reads as data corruption rather than as a bug. Bind state too: the marks live there, and a table with no state binding has nowhere to keep them. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  getRowId: row => row.id,   // ⚠️ not optional once anything marks a cell
{{ "}" }});

5. The state shape

Three collections, and the split is the point. A cell picked on its own is enumerated; a contiguous block is a descriptor — an anchor, a focus, and the columns it spans — whose membership is answered by a predicate rather than materialised. Highlighting one column of a 10,000-row table as a per-cell map would be ~270 KB of JSON re-emitted on every state change, and a few such columns would exceed Firestore's 1 MiB document limit. A descriptor is one object whatever the row count.

exclusions is what makes a click a real toggle. Clicking a cell that a block covers has to be able to un-highlight it — and a rectangle minus a cell is not a rectangle, so the block cannot simply be reshaped. Subtracting instead keeps the descriptor intact and records the hole, and it stays bounded for the same reason cells does: a user removes cells one at a time. Clicking the cell again drops the exclusion and the block takes over again; shift-clicking the same block a second time removes the block outright. 

interface NgeHighlightState {{ "{" }}
  anchor: string | null;          // "rowId::columnId", where a shift-click extends from
  cells: string[];                // individually picked
  exclusions: string[];           // individually removed — beats ranges
  ranges: NgeHighlightRange[];   // contiguous blocks, as descriptors
{{ "}" }}

6. Export only what is highlighted

The composition the gate exists to prove. The export seam takes a cellPredicate and has never heard of highlighting; the highlight addon supplies one and has never heard of exporting. Neither file imports the other — they meet on the table instance. 

const table = viewChild.required<NgeTableComponent<Row>>('table');

table().readNgeExportData({{ "{" }} cellPredicate: highlight.predicate() {{ "}" }});

7. Persisting a user's view

The slice is plain JSON by construction, so it round-trips through JSON.stringify unchanged and stores alongside the sort, the column widths, and the pinning. Restoring is silent — pushing state in through [state] is not the table doing something, so it emits no NgeTableEvent. 

await setDoc(viewRef, {{ "{" }} table: state() {{ "}" }});   // save
state.set(snapshot.data().table);            // restore — silent
