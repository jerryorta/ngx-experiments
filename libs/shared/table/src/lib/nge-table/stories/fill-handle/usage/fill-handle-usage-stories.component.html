NgeTable — Fill Handle Usage

The fill handle is one more component in the cell-overlay template — but unlike every other feature here, switching it on is not enough. The library owns no data, so it proposes a change and stops. A host that does not listen gets a handle that drags, outlines, and changes nothing. No example below imports @tanstack/*.

1. The template — both components, one slot

⚠️ cell-overlay resolves to one template per column plus one shared fallback, so a second ngeTableSlot="cell-overlay" would silently replace the first rather than compose with it. With three cell-marking components in the library, the consumer hosts them together. 

<nge-table [config]="config()" [(state)]="state" (ngeTableEvent)="onEvent($event)">
  <ng-template ngeTableSlot="cell-overlay" [ngeTableSlotOf]="rows()" let-cell>
    <nge-range-overlay [cell]="cell" [state]="state()" />
    <nge-fill-handle  [cell]="cell" [state]="state()" />
  </ng-template>
</nge-table>

Providers are the ones you already have for cell ranges — the fill feature registers alongside them and is inert until a handle is projected. 

@Component({{ "{" }}
  providers: [provideNgeCellRange()],
  imports: [NgeTableComponent, NgeTableSlotDirective,
            NgeRangeOverlayComponent, NgeFillHandleComponent],
{{ "}" }})

2. Applying the intent — the part only you can write

fill-intent is the one event kind you are expected to act on. Every other kind reports something already done; this one reports something the table will not do on its own. 

onEvent(event: NgeTableEvent<Row>): void {{ "{" }}
  if (event.kind !== 'fill-intent') {{ "{" }} return; {{ "}" }}

  const patches = new Map<string, Record<string, unknown>>();
  for (const cell of event.cells) {{ "{" }}
    const patch = patches.get(cell.rowId) ?? {{ "{" }}{{ "}" }};
    patch[cell.columnId] = cell.value;
    patches.set(cell.rowId, patch);
  {{ "}" }}

  // New objects only where something changed, so untouched rows keep their
  // identity and the engine's memoisation survives the edit.
  this.rows.update(rows => rows.map(row => {{ "{" }}
    const patch = patches.get(row.id);
    return patch ? {{ "{" }} ...row, ...patch {{ "}" }} : row;
  {{ "}" }}));
{{ "}" }}

3. Undo — the same walk, the other field

Every proposed cell carries previousValue, so reversing a fill is the same loop reading the other field. Undo belongs to you because the data does. 

undo(): void {{ "{" }}
  const cells = this.lastIntent();
  if (cells) {{ "{" }} this.applyFill(cells, cell => cell.previousValue); {{ "}" }}
{{ "}" }}

⚠️ It is not a guarantee of reversibility: if your data moved between the emission and the undo, you are reversing against a table that no longer matches. That is inherent to owning the data.

4. Opting a column out

A derived or read-only column must never be a fill target. It stays usable as a source — its values can seed a neighbour's series. 

{{ "{" }}
  id: 'total',
  header: 'Total',
  accessorFn: row => row.price * row.quantity,
  meta: {{ "{" }} ngeFill: {{ "{" }} enabled: false {{ "}" }} {{ "}" }},
{{ "}" }}

Namespaced under ngeFill beside ARCH-248's ngeExport, because ColumnMeta is one globally-merged interface every addon shares.

5. What the fill infers

Two behaviours, inferred from the source rather than configured: 

[7]              → 7, 7, 7        copy — one cell is not a series
['a','b']        → a, b, a, b     copy, cycling the pattern
[10, 20]         → 30, 40, 50     linear, step (last − first) / (n − 1)
[1, 3, 5]        → 7, 9           the step spans the WHOLE source
[5, 5, 5]        → 5, 5           a series whose step is zero
[10, 20] upward  → …, −10, 0      backwards changes the arithmetic

The drag is two-dimensional — each axis resolves independently, so one gesture can grow the rows and shrink the columns. Growing both at once fills in two passes: rows from the real source, then columns across every row including the new ones, which is what gives the corner quadrant its values. 

2×2 source dragged out to 4×3

   A    B    C          [ ] = source
0 [10] [20]  30         ↧   = pass 1 (rows, from A–B)
1 [15] [25]  35         ↦   = pass 2 (columns, from each row's A–B)
2  20   30   40         ⇘   = the corner: pass 2 reading pass 1
3  25   35   45

Date series, text patterns (Q1 → Q2) and custom handlers are deliberately out of scope — they are mintable once this write path has proven itself.

6. When there is no handle

The grip appears on the active range's trailing-bottom corner — and not at all when that range is unbounded on the row axis: a whole column, or cmd/ctrl-A. Such a range covers every row, so there is no corner and nothing below it to fill into.
