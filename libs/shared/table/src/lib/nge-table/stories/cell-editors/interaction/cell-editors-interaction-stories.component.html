NgeTable — Cell Editors (Interaction)

Two editors ship from @nge/table/editors: <nge-cell-input> and <nge-cell-checkbox>. A column names one in meta.ngeEdit.editor and the table renders it — there is no template to write, and <nge-table>'s own markup gains no branch, because the component resolves through the same render-slot registry a projected [ngeCell] goes through.

Nothing here writes your data. Committing announces an edit-intent and stops; the demo component wrapping each table applies the patch to its own rows. Section 7 turns that listener off to show what the library does on its own.

⚠️ This page needs a human in a foregrounded tab. An untrusted event triggers no browser default, so a scripted space never types a character and a scripted drag never selects text — and an automation tab is visibilityState: 'hidden', which suspends requestAnimationFrame so zoneless change detection never flushes and activation reads as broken when it is not.

1. The input, with no template written

Click a cell in Name, Quantity or Description. A field appears, already focused and holding the current value. enter or clicking away commits; esc abandons it.

⚠️ The focus is not decoration. Tab to a row and press enter — the row is a tab stop because the table is editable, and activation focuses nothing on its own, so without the editor focusing itself a keyboard-only user would open a field they could not type into.

Quantity is a number field, declared as editorInputs: {{ "{" }} type: 'number' {{ "}" }}. Clear it, or type letters, and commit: the edit is abandoned rather than proposing a NaN the host would write into its row.

2. The checkbox, always live

Active declares alwaysLive: true, so its box is a real control with a real tab stop from the first render. Tab into the column and press space: the value is proposed immediately and the readout below records it.

⚠️ A toggle IS the commit here, and that is a correctness decision rather than a shortcut. A half-typed string is worth holding; a flipped checkbox is not, and holding one is unsafe — [checked] re-derives from the cell, and Angular writes a property binding only when the bound value changes, so a box unchecked on a true row and recycled onto another true row would keep showing the stale state.

⚠️ Note what does not happen: the column is live for every rendered row, and no row stole focus when the table painted. Focus follows the transition into editing, which an always-live column never makes.

3. The same checkbox left on activation

The same column with alwaysLive off. The box shows the value but is disabled until the cell is clicked — the read-only half of the activation model, showing a value without offering to change it.

It works, and it is not what the control is for: activation exists to avoid building controls nobody engaged, and a checkbox is the cheapest control there is, so the saving is nil while the cost — a click to activate before the click that toggles — is real. Compare the two sections and prefer section 2 for a boolean column.

4. A consumer's own template still wins

The same configuration with a [ngeCell] template projected for Name. That column now renders the consumer's uppercased read-only cell and the library's editor is never reached for it — while Quantity, Description and Active still use theirs.

⚠️ This is the resolution order, not a coincidence. The store consults the projected templates first and only then the editor a column named. ARCH-278 recorded what the other order costs: it "compiles, lints and renders perfectly while silently ignoring every consumer template".

5. Keyboard containment, with cell ranges switched on

Cell range selection is on for this table. Drag across a few cells to build a range, then open an editor and try each key:

  • space types a space rather than toggling row selection.
  • esc cancels the edit and leaves the range alone — the key is contained at the cell, which starves the range and highlight addons' document-level listeners at once without core knowing either exists.
  • cmd/ctrl-a selects the field's text rather than every cell.
  • Drag from inside a field: it selects text and no cells. The same guard covers the checkbox.

6. Scrolling an open editor out of the window

2,000 virtualized rows. Open an editor near the top, type something, then scroll far enough for its row to leave the window and scroll back.

⚠️ The edit is cancelled, and that is the correct outcome. Virtualization recycles DOM, so a draft that survived its row leaving would belong to whichever record the recycled element shows next — the shape of a bug that reads as data corruption rather than as an edit correctly abandoned.

7. A host that ignores the intent

The same table with the edit-intent handler switched off. Edit a cell and commit it: the editor opens, the value is collected, the proposal arrives in the readout — and the table does not change.

⚠️ This is correct behaviour, not a bug. The library owns no data, so it announces the patch and waits. Owning the editors changes nothing about that boundary.
