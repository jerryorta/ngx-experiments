NgeTable — Cell Editors (Theming)

The editors theme through --nge-table-editor-*, declared with literal light-mode defaults in _table-tokens.scss and paired with a literal fallback at every use site — so a field renders correctly with no theme applied at all.

⚠️ Most of this needs a gesture. Activation is the default, so a field only exists once a cell is engaged: click into Name, Quantity or Description in each section to see the tokens it declares. The Active column is always live, so its box is visible at rest.

1. The library defaults

No wrapper class, nothing overridden. This is what a consumer sees before they have said anything — the property the whole token contract exists to preserve.

2. Surface, content and border

A field has to read as sitting on the row rather than as part of it, which is why the editors carry a surface token of their own instead of inheriting --nge-table-surface: on a themed table the two routinely resolve to the same colour, and a field that inherited it would have only its border to say it is a control. 

.my-table {{ "{" }}
  --nge-table-editor-surface: #fff8e1;
  --nge-table-editor-on-surface: #4a3800;
  --nge-table-editor-border-color: #c8a415;
{{ "}" }}

3. The accent and the focus border

--nge-table-editor-accent tints the native checkbox through accent-color, which is what keeps the box keyboard-, screen-reader- and high-contrast-correct for free. It is separate from --nge-table-selection-accent on purpose: ARCH-268's selection box and an editing box mean different things, and a theme may well want to say so.

⚠️ Click into a field to see the rest. --nge-table-editor-border-color-focus only applies while the field holds focus, and the ring inside it is --nge-table-focus-ring-color — reused rather than duplicated, and drawn inset because .nge-table__cell carries overflow: hidden and would clip an outer one away. 

.my-table {{ "{" }}
  --nge-table-editor-accent: #8e24aa;
  --nge-table-editor-border-color-focus: #8e24aa;
  --nge-table-focus-ring-color: #8e24aa;
{{ "}" }}

4. Geometry

Radius, border width, horizontal padding and the checkbox's size. A field's height is deliberately not a token: it is derived from --nge-table-row-height, so a table at any density gets a field that matches it with no second number to keep in step. 

.my-table {{ "{" }}
  --nge-table-editor-radius: 0;
  --nge-table-editor-border-width: 2px;
  --nge-table-editor-padding-x: 12px;
  --nge-table-editor-control-size: 20px;
{{ "}" }}

5. A dark section — the shape a domain bridge takes

All ten domain themes bridge five of these tokens onto their own variables (ARCH-277's arrangement, extended in ARCH-293): surface, content, border, focus border and accent. Geometry and type size are left alone, for the reason every bridge leaves them alone — a bridge entry that teaches a contract the table does not honour is worse than no entry.

⚠️ Restate every surface rather than letting any inherit. Click into a field: a field left on the light default is a white rectangle punched through a dark table, and it is the exact failure a missed pinned surface produces. 

.cg-professional-dark {{ "{" }}
  --nge-table-editor-surface: var(--cg-surface-container);
  --nge-table-editor-on-surface: var(--cg-on-surface);
  --nge-table-editor-border-color: var(--cg-outline);
  --nge-table-editor-border-color-focus: var(--cg-secondary);
  --nge-table-editor-accent: var(--cg-secondary);
{{ "}" }}

6. Which of these a theme should set

Sections 2, 3 and 5 are a theme's business — they carry colour, and a domain has an opinion about colour. Section 4 is not: geometry belongs to whoever is laying the table out, and --nge-table-editor-font-size defaults to inherit so a field already matches the table's type without anyone saying so.

The test that decides it, unchanged from ARCH-277: would a bridge entry here teach a contract the table does not honour? If yes, the token is not a theme's business.
