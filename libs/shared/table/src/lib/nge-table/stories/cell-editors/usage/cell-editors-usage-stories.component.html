NgeTable — Cell Editors (Usage)

The table ships two editors of its own. They live behind a third entry point, @nge/table/editors, so the production barrel never reaches them — most tables display rather than edit, and a dependency an editor needs must not become the table's.

They are defaults, not fixtures: a [ngeCell] template for the same column shadows whichever editor it named, so adopting one is never a decision you have to unpick later.

1. Naming an editor on a column

meta.ngeEdit.enabled puts a column into the activation model; meta.ngeEdit.editor says what to render while it is being edited. There is no template to write and no directive to import. 

import {{ "{" }} NgeCellInputComponent {{ "}" }} from '@nge/table/editors';

const columns: NgeTableColumn<Row>[] = [
  {{ "{" }}
    accessorKey: 'name',
    header: 'Name',
    id: 'name',
    meta: {{ "{" }} ngeEdit: {{ "{" }} editor: NgeCellInputComponent, enabled: true {{ "}" }} {{
            "}"
          }},
  {{ "}" }},
];

2. Configuring the editor a column named

editorInputs carries whatever inputs that editor declares — the number mode, a label better than the column id. It exists so an option is never a reason to fall back to writing a template.

⚠️ Only inputs the component actually declares are applied: the adapter filters by the component's reflected input names, so a misspelled key is dropped in silence. Check the rendered control rather than the console when an option seems to do nothing. 

meta: {{ "{" }}
  ngeEdit: {{ "{" }}
    editor: NgeCellInputComponent,
    editorInputs: {{ "{" }} label: 'Edit quantity', type: 'number' {{ "}" }},
    enabled: true,
  {{ "}" }},
{{ "}" }}

The Quantity column of every table on this page is declared exactly that way. It commits a number rather than its text, so a host applying the patch writes the type its row already had.

3. The boolean column

<nge-cell-checkbox> is a focusable control with a real tab stop — deliberately not ARCH-268's selection checkbox, which is a pointer affordance (tabindex="-1", aria-hidden) announced by the row it sits in.

Pair it with alwaysLive: true. Activation exists to avoid building controls nobody engaged, and a checkbox is the cheapest control there is, so the saving is nil while the extra click is real. 

import {{ "{" }} NgeCellCheckboxComponent {{ "}" }} from '@nge/table/editors';

meta: {{ "{" }}
  ngeEdit: {{ "{" }}
    alwaysLive: true,
    editor: NgeCellCheckboxComponent,
    editorInputs: {{ "{" }} label: 'Active' {{ "}" }},
    enabled: true,
  {{ "}" }},
{{ "}" }}

4. Applying the edit — still the host's job

Owning the editors changes nothing about the data boundary. A commit announces an edit-intent carrying the same NgeCellPatch shape fill-intent uses, and the table's own data is unchanged until the host hands new rows back in. Ignoring the event means the edit does not happen — correct for a host that has not opted into editing. 

onEvent(event: NgeTableEvent<Row>): void {{ "{" }}
  if (event.kind !== 'edit-intent') return;
  this.rows.update(rows => applyPatches(rows, event.cells));   // the host's own write
{{ "}" }}

⚠️ config.getRowId stops being optional the moment a column sets meta.ngeEdit.enabled. An edit is id-keyed scratch state, so without one a sort or a re-fetch would land the patch on a different record; the library throws in dev rather than degrade.

5. Replacing an editor with your own control

Project a [ngeCell] template for the column and it wins. The store consults the projected templates first and only then the editor a column named, so a domain dropping its own dlc-input into a cell never has to remove the meta entry. 

<nge-table [config]="config" [(state)]="state">
  <ng-template ngeCell="name" [ngeCellOf]="rows" let-cell>
    @if (cell.isEditing()) {{ "{" }} <dlc-input [value]="cell.value" … /> {{ "}" }}
    @else {{ "{" }} {{ "{" }}{{ "{" }} cell.value {{ "}" }}{{ "}" }} {{ "}" }}
  </ng-template>
</nge-table>

Below, Name is shadowed by a read-only uppercased template while every other editable column still uses the library's editor.

6. What these editors deliberately are not

A cell editor is not a form control, and that is what makes it cheap: no ControlValueAccessor, no NgControl, no label element, no validation, no touched or dirty tracking. There is no form. That per-instance saving is the justification for the table owning an editor rather than reaching for a design-library input.

They also hold no draft. The field's own DOM value is the draft, which is safe because activation bounds the element's life — and the checkbox commits on toggle for the same reason, since an always-live column has no such bound.
