NgeTable — Chart Cells (Theming)

There is no config.theme here either. The only new visual surface ARCH-291 adds is <nge-cell-shell>, and it themes through --nge-table-shell-* custom properties, each paired with a literal fallback at its use site. It declares nothing in _table-tokens.scss — editing that partial would be a core edit — so every override below is a scoped wrapper class, exactly what a consumer writes.

1. The resolved chart cell — almost nothing left to theme

Once isSettled() is true, the shell is gone and <nge-chart>'s own palette — the charts library's contract — is what a reviewer sees. But the cell's wrapper (.chart-cell) keeps reading the same --nge-table-shell-* pair as its background and radius, deliberately: the chart debounces its own render by 16ms, so this backing box is what shows for that first frame instead of an unthemed flash. Section 3 makes that visible. This table is not virtualized, so it never shows the shell itself.

3. The shell's own tokens

Requiring a scroll gesture before three palettes could be compared side by side would defeat the point of a theming story — the same reason highlight/theming seeds its marks instead of requiring a click. The three boxes below render <nge-cell-shell> directly, sized like the chart column above, so they are comparable at a glance. 

.theme-inherited {{ "{" }}
  /* No --nge-table-shell-surface at all — only the CORE token most themes already bridge. */
  --nge-table-surface-variant: #dceeff;
{{ "}" }}

.theme-tinted {{ "{" }}
  --nge-table-shell-surface: #fde8d0;
  --nge-table-shell-radius: 12px;
{{ "}" }}
Default — no overrides
Inherits --nge-table-surface-variant
Explicit --nge-table-shell-surface + radius

The middle box sets only the CORE --nge-table-surface-variant token — nothing shell-specific — and the shell already follows it, which is the "no eleventh bridge entry" claim made concrete. The third box sets --nge-table-shell-surface explicitly, which wins over the core token even where both are set.

And the chart, wrapped in the same three theme classes below. The chart's own wrapper reads the identical token pair — deliberately, not by coincidence — so the shell → chart handoff never flashes an unthemed box behind the arriving chart. Watch the thin edge around each sparkline, at its own small margin: same colour, same corner radius, as the shell box above it.

4. Outside a cell — min-height and inset

--nge-table-shell-min-height and --nge-table-shell-inset are only reachable when the shell sits inside a table cell that hands it a definite height via align-self: stretch — the exact case a story panel is not. The two rows below drop <nge-cell-shell> with no sizing wrapper at all, the way a consumer's own skeleton row would. 

.theme-roomy-shell {{ "{" }}
  --nge-table-shell-min-height: 48px;
  --nge-table-shell-inset: 2px;
{{ "}" }}
Default — 12px min-height, 6px inset
Roomy — 48px min-height, 2px inset
