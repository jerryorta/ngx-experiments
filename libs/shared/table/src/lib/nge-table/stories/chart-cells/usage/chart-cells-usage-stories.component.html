NgeTable — Chart Cells (Usage)

A chart in a cell is an ordinary application of the render-slot seam (ARCH-246): a [ngeCell] template branching on cell.isSettled(). The library defines nothing about chart data — the column below is entirely consumer code, and no example imports @tanstack/*.

1. Basic usage

@if (cell.isSettled()) draws the real thing; @else draws <nge-cell-shell>, a flat, un-animated placeholder the table ships for exactly this branch. This table is not virtualized, so isSettled() is always true here and only the chart branch ever runs — see the Interaction story for the shell actually appearing. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: [seriesColumn, ...NGE_TABLE_FIXTURE_COLUMNS.slice(0, 3)],
  data: createNgeTableFixture({{ "{" }} rows: 8 {{ "}" }}),
  getRowId: row => row.id,
  rowHeight: 96,
{{ "}" }});

<ng-template ngeCell="series" [ngeCellOf]="rows" let-cell>
  @if (cell.isSettled()) {{ "{" }}
    <div class="chart-cell"><nge-chart [config]="chartFor(cell.row)" /></div>
  {{ "}" }} @else {{ "{" }}
    <nge-cell-shell />
  {{ "}" }}
</ng-template>
@if (cell.isSettled()) {
} @else { }

2. The transform must be memoised

The library defines nothing about chart data; the consumer supplies a pure transform and memoises it. A factory called straight from the template — chartFor(cell.row) — runs on every change-detection pass, and a fresh object every time would change <nge-chart>'s config input identity, which re-renders the chart. Under virtualization that is exactly the cost isSettled exists to avoid, so the cache below is not an optimisation on top of the pattern — it is the pattern. 

private readonly chartConfigs = new Map<string, NgeChartConfig>();

chartFor(row: Row): NgeChartConfig {{ "{" }}
  const cached = this.chartConfigs.get(row.id);
  if (cached) {{ "{" }} return cached; {{ "}" }}

  const config = createSparklineChartConfig({{ "{" }}
    animationMs: 0,                              // no per-slide strobe under virtualization
    data: row.series.map((y, x) => ({{ "{" }} x, y {{ "}" }})),
    yDomain: [0, 100],                            // the fixture's shared, comparable range
  {{ "}" }});

  this.chartConfigs.set(row.id, config);
  return config;
{{ "}" }}

3. The array-valued column's opt-outs

A cell reading a readonly number[] forces two decisions no other column in the fixture has to make. Sorting a number[] is meaningless, so the column declares enableSorting: false. And the export seam's default formatter is String(value), which comma-joins an array — legible, but not what belongs in an exported file — so the column declares its own meta.ngeExport.format instead. 

const seriesColumn: NgeTableColumn<Row> = {{ "{" }}
  accessorKey: 'series',
  enableSorting: false,
  header: 'Trend',
  id: 'series',
  meta: {{ "{" }}
    ngeExport: {{
            "{"
          }} format: value => (Array.isArray(value) ? value.length + ' points' : '') {{ "}" }},
  {{ "}" }},
{{ "}" }};

Called against the first row's series above: {{ sampleFormattedSeries }}. Without the override, String(value) would instead comma-join all twelve numbers into the field.

4. Row height is what gives the sparkline room

rowHeight is presentational everywhere else in this library; here it decides whether the sparkline has room to draw at all. <nge-chart> attaches a shadow root that injects :host, svg {{ "{" }} width: 100%; height: 100% {{ "}" }}, and that percentage resolves against .nge-table__cell's own height — always definite (the row's --nge-table-row-height), never auto. A chart does not collapse in a table cell; it is simply squeezed into whatever the row allows. The Interaction story renders the library's 40px default beside rowHeight: 96 so the difference is visible.

The .chart-cell wrapper below is still worth keeping, for a different reason than avoiding a collapse: align-self: stretch is the same sizing <nge-cell-shell> already uses against this identical cell, so the shell and the chart share one convention rather than two.

⚠️ That convention is a cell's, and it does not carry to every surface. It works here because a cell is a flex item on a row whose height is already definite, so stretching resolves it. A row-detail band declares a height of its own (config.rowDetailHeight) but is a plain block on its own line — there is no flex line to stretch against, so content there claims the height by reading --nge-table-row-detail-height instead. See Row Detail Content → Usage for that case. 

config = createNgeTableConfig<Row>({{ "{" }} columns, data, getRowId, rowHeight: 96 {{
            "}"
          }});

.chart-cell {{ "{" }} flex: 1 1 auto; align-self: stretch; min-width: 0; {{ "}" }}

5. The shared domain keeps rows comparable

Every sparkline in the table above shares yDomain: [0, 100] — the fixture's own bound on series (ARCH-290). Reading down the column, a row that climbs draws a taller line than a row that stays flat, because both are plotted against the same scale. Drop yDomain and each cell auto-scales to its own row's min and max instead — a flat-looking walk between 40 and 45 would fill the cell exactly as fully as a dramatic one between 0 and 100, and the column would stop being twelve comparable pictures and become twelve unrelated ones.

6. The shell is generic, not chart-specific

<nge-cell-shell> belongs to the table rather than to charts, and nothing about it names a chart. It is the cheap thing any expensive cell can draw while the table is busy — an image, a map, a third-party widget — with no cooperation from whatever renders once isSettled() is true.
