NgeTable — Chart Cells (Interaction)

NgeCellContext.isSettled is a signal every cell template receives, answering whether the scroll has been quiet long enough to draw something expensive. It carries no slice of NgeTableState — there is nothing here to persist or push in from outside, so the sections below drive the signal directly and read it back live instead of showing a state JSON.

1. The shell↔chart switch, driven by scroll

Scroll the table below quickly, in both directions. While it is moving, the Trend column fills with flat <nge-cell-shell> blocks; about 150ms after you stop, they resolve into sparklines. The badge beside each one reads cell.isSettled() directly — every cell's context closes over the same underlying signal, so whichever one you look at reports the table's current state.

2. Without virtualization, the switch never trips

Same column, same chartFor, same 96px rows — only enableVirtualization is missing. The badge below reads chart from first paint and stays that way regardless of how you scroll the page around it. This is the honest degradation the signal's own doc comment describes: a table that renders every row builds each cell once and never recycles it, so there is no per-slide cost for a shell to save.

3. Row height, not a wrapper, gives the chart its room

<nge-chart> attaches a shadow root that injects :host, svg {{ "{" }} width: 100%; height: 100% {{ "}" }}. That percentage resolves against .nge-table__cell's own height — which is always definite (the row's --nge-table-row-height), never auto — so a bare <nge-chart> with no wrapping <div> renders at the cell's full height regardless of the cell's align-items. It does not collapse in a table cell. What it needs is a tall enough row: both tables below use the identical wrapped pattern from Example 1 and differ only in rowHeight. 

config = createNgeTableConfig<Row>({{ "{" }} columns, data, getRowId {{ "}" }});
// rowHeight omitted → falls to NGE_TABLE_DEFAULTS.rowHeight (40px)

config = createNgeTableConfig<Row>({{ "{" }} columns, data, getRowId, rowHeight: 96 {{
            "}"
          }});

The wrapper is still worth keeping, for a different reason than avoiding a collapse: it is the same align-self: stretch sizing <nge-cell-shell> uses against this identical cell, so the shell and the chart share one sizing convention rather than two. ⚠️ It is a cell's convention, though: it resolves because a cell is a flex item on a row of definite height. A row-detail band has a declared height too (config.rowDetailHeight) but is a block on its own line, so its content reads --nge-table-row-detail-height rather than stretching — see Row Detail Content.
