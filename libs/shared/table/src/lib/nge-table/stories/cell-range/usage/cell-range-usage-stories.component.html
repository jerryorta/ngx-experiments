NgeTable — Cell Range Selection (Usage)

Cell ranges are an addon over <nge-table>: a TableFeature for the state and the export predicate, the existing cell-overlay slot for the paint, and a per-table bridge that owns the pointer gesture. It touches no file in the library core. Two lines switch it on; the third — binding state — is what makes it work.

1. Switch it on

One entry in providers. It registers three things: the feature that owns the state slice and the export predicate, the NgeRangeBridge a projected template resolves, and the hand-off between them. 

@Component({{ "{" }}
  providers: [provideNgeCellRange()],
  …
{{ "}" }})

⚠️ Put it on the component that hosts the table, never in an application's root providers — a range is per-table, exactly as NgeTableStore is. See section 8.

2. Project the overlay

One template covers every column: the slot registry falls back to a shared registration when a column has none of its own. The overlay renders nothing — it carries a class and publishes its cell's id pair, and the addon's stylesheet paints the cell around it with :has(). 

<nge-table [config]="config" [(state)]="state">
  <ng-template ngeTableSlot="cell-overlay" [ngeTableSlotOf]="rows" let-cell>
    <nge-range-overlay [cell]="cell" [state]="state()" />
  </ng-template>
</nge-table>

⚠️ The overlay is not optional if the gesture is wanted. It stamps the data-nge-range-cell attribute every hit-test reads, and it is what hands the bridge the table root the pointer listeners are delegated from. A table that provides the addon and projects no overlay has state and export composition and no pointer behaviour at all — which is a supported arrangement, but rarely the intended one. See section 9.

[ngeTableSlotOf] is the type carrier, not decoration. Without it TRow resolves to unknown and any field access on let-cell fails to compile.

3. getRowId and state are both compulsory

Every rectangle names its corners by row id. Without getRowId the engine keys rows by array index, so a sort, a filter or a re-fetch moves the selection onto different records — so this one throws in development rather than degrading quietly. And the rectangles live in state, so a table with no state binding has nowhere to keep them across a rebuild. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: createNgeTableFixture({{ "{" }} rows: 25 {{ "}" }}),
  getRowId: row => row.id,          // ⚠️ mandatory
{{ "}" }});
state.ngeRange
{{ stateJson() }}

4. What the state looks like

A rectangle is a descriptor — four ids naming two opposite corners — never a map of the cells it covers. Which cells lie between the corners is resolved at read time, rows against the processed row model and columns against the visible leaf columns in visual order. That is what makes the slice four strings regardless of how much it covers, and what makes a sort or a pin re-shape a block rather than strand it. 

interface NgeCellRange {{ "{" }}
  anchorColumnId: string;   // the corner the block is anchored on
  anchorRowId: string;
  focusColumnId: string;    // the moving corner — drag, shift-click, keyboard
  focusRowId: string;
{{ "}" }}

interface NgeRangeState {{ "{" }}
  ranges: NgeCellRange[];  // disjoint rectangles, oldest first; the LAST is active
{{ "}" }}

It is plain JSON by construction, so it inherits the persistability promise NgeTableState makes — a user's selection saves and restores with the rest of their view.

5. Per-table options

Four, all optional, all resolved per provider scope. 

provideNgeCellRange({{ "{" }}
  autoScrollSpeed: 12,          // px per frame at the viewport boundary (the ceiling, not a constant)
  autoScrollThreshold: 48,      // how close to an edge a drag starts scrolling
  clearOnEscape: true,          // give up the selection on Escape
  selectAllOnModifierA: true,   // take cmd/ctrl-A once the user has engaged with this table
{{ "}" }})

⚠️ Both key listeners are on the document, because nothing in a table body is focusable and a scoped handler would never fire. So on a page with several range-enabled tables, one Esc clears them all — pass clearOnEscape: false on every table but the one that should own the key. This story's own tables do exactly that.

autoScrollSpeed is a ceiling rather than a constant: the speed ramps from nothing at the edge of the threshold up to this at the boundary, so a nudge creeps and a shove runs.

6. Driving it from your own controls

The gesture needs no wiring, but a toolbar might. Inject the bridge and call it with the same ids the render slots and the cell-click event carry — no @tanstack/* type crosses the boundary. 

private readonly range = inject(NgeRangeBridge);

start(rowId: string, columnId: string): void {{ "{" }}
  this.range.start(rowId, columnId);                      // a 1×1 rectangle, replacing
  this.range.start(rowId, columnId, {{ "{" }} additive: true {{
            "}"
          }});   // …or appending a disjoint one
{{ "}" }}

extend(rowId: string, columnId: string): void {{ "{" }}
  this.range.extendTo(rowId, columnId);   // moves the ACTIVE rectangle's focus; the anchor stays
{{ "}" }}

selectAll(): void {{ "{" }} this.range.selectAll(); {{ "}" }}
clear(): void {{ "{" }} this.range.clear(); {{ "}" }}

⚠️ There is deliberately no hasRanges() on the bridge. It holds the raw engine instance, whose options refresh only when the adapter's proxy is read — an application reads the proxy constantly so the staleness would be invisible, and a spec does not. Derive a disabled state from the state you already own: 

readonly hasRanges = computed(() => (this.state().ngeRange?.ranges.length ?? 0) > 0);

7. Exporting only what is selected

The bridge hands over a predicate in exactly the shape the export seam takes. Neither addon imports the other; they meet on the table instance and nowhere else. 

private readonly table = viewChild.required(NgeTableComponent<Row>);

exportSelected(): NgeTableExportData {{ "{" }}
  return this.table().readNgeExportData({{ "{" }} cellPredicate: this.range.predicate() {{ "}" }});
{{ "}" }}

Select a block below, then export. A predicate-narrowed export is ragged by design — a column with no selected cell contributes nothing to that row. Feed the result to toNgeCsv() and the composition is three addons deep with no coupling between any of them.

8. One provider scope per table

provideNgeCellRange() registers one bridge per injector, and that bridge holds both the engine instance and the table root its pointer listeners are delegated from. A component rendering several range-enabled tables therefore needs one provider scope each — the last table to attach wins, so a drag in the first would resolve its cells against the last one's rows. 

// ❌ one bridge, three tables — the last to attach wins
@Component({{ "{" }} providers: [provideNgeCellRange()] {{ "}" }})
class Dashboard {{ "{" }} /* renders three <nge-table> */ {{ "}" }}

// ✅ a small component owning ONE table, its state, and its interactions
@Component({{ "{" }} providers: [provideNgeCellRange()], selector: 'my-range-table' {{ "}" }})
class MyRangeTable {{ "{" }} /* renders one <nge-table> */ {{ "}" }}

The second shape is what a real consumer converges on anyway, and it is what every table on these three story pages uses. One further consequence worth knowing: options are a useValue on the provider scope, so per-instance option differences mean a second component class rather than an input.

9. State and export without a gesture

The three registrations are separable. A consumer who wants range-narrowed export driven by their own logic — a saved query, a rule engine — can register the feature alone and project no overlay: the slice, readNgeRangeState() and the export predicate all work, and there is no pointer behaviour and no paint. 

@Component({{ "{" }}
  providers: [provideNgeTableFeatures(ngeCellRange)],
  …
{{ "}" }})

Nothing in these examples imports @tanstack/*, including this one — the feature is re-exported behind the nge surface, which is what keeps a future engine major internal to the library.
