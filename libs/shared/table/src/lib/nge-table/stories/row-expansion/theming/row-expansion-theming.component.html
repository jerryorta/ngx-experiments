NgeTable — Row Expansion (Theming)

There is no config.theme on NgeTableConfig. The table themes exclusively through --nge-table-* custom properties, so every section below is a scoped wrapper class re-declaring tokens — exactly what a consumer overriding them would write. Most share one config, because theming changes nothing about configuration.

1. The band's surface

--nge-table-row-detail-surface exists so an open band reads as attached to its row rather than as a new one. It has been part of the contract since Wave 0 and is bridged across all ten domain themes.

2. The chevron takes the muted foreground

The disclosure control reads --nge-table-on-surface-variant — the same token the sort indicator takes, rather than a colour of its own. Both are a small monochrome glyph beside content, so a theme with an opinion about one has the same opinion about the other, and a token of its own would mean ten bridge entries teaching nothing this one already says.

default
--nge-table-on-surface-variant: #6a1b9a

3. The band's height — the one that is conditional

⚠️ This is the geometry trap in a new place, and it fails silently. While virtualization is on, <nge-table> publishes the resolved --nge-table-row-detail-height as an inline custom property on the host — where it beats a wrapper class outright, because an inline declaration outranks a class selector regardless of specificity.

That is deliberate rather than an oversight: a virtualized row is positioned as rowHeight + rowDetailHeight, so a theme moving the band alone would not restyle the table — it would put the band and the row beneath it in disagreement about where the row ends, and the result is an overlap rather than a different look.

Off virtualization a theme owns the token outright. The left table below is hand-authored with rowDetailHeight omitted — the supported path, since the factory fills it in unconditionally — and its wrapper class moves the band. The right table is virtualized, and the identical wrapper class does nothing.

The band takes that value as a definite height in both regimes, and content taller than it scrolls rather than growing the band. That is what makes the open animatable at all (section 6): a transition needs two definite endpoints, and a band sized by its own content has none.

not virtualized · class sets 200px · moves
{{ detail.row.owner.name }}
virtualized · same class · stays at the config's 140px
{{ detail.row.owner.name }}

6. How long the band takes to get there

--nge-table-row-detail-duration is the band's other token, and the easiest tier of the four: nothing in TypeScript reads it, so a wrapper class always wins. Both tables below share one state, so a single chevron opens both bands in the same frame — the comparison is an A/B rather than two openings to time by eye.

0ms is a supported value, not an edge case. It is how a consumer with a house rule against motion opts out without writing a media query, and how a test gets the band at its final height on the next frame. The accessibility switch is separate and cannot be overridden by a theme: under prefers-reduced-motion: reduce the library declares transition: none on the band and on the chevron, which an inline duration cannot outrank.

--nge-table-row-detail-duration: 600ms
{{ detail.row.owner.name }}
--nge-table-row-detail-duration: 0ms
{{ detail.row.owner.name }}

7. Which of these tokens are yours

Row expansion touches all four of the contract's tiers, and the third one is the reason this story has a section 3.

Tier Tokens Themeable from a wrapper class?
Read from CSS --nge-table-row-detail-surface, --nge-table-on-surface-variant Yes
Overwritten inline while virtualizing --nge-table-row-detail-height Only when the config omits rowDetailHeight — see section 3
Read from CSS, with no TypeScript counterpart at all --nge-table-row-detail-duration Yes, always — the animation is CSS end to end, which is also why it costs the scroll nothing and why reduced motion can switch it off without the engine hearing about it
Mirrored in TypeScript --nge-table-expansion-column-width No — the injected column's size reads NGE_TABLE_DEFAULTS, so the token alone would style a lane the engine still measured at another width
