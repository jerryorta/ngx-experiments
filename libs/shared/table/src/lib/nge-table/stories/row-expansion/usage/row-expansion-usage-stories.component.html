NgeTable — Row Expansion (Usage)

The whole surface is two config fields, one render slot, and a state slice that has been part of NgeTableState since Wave 0 — which is what shipping the state contract whole was for. No example here imports @tanstack/*.

1. Basic usage

Switch the flag on, give the table a stable row identity, and project a row-detail template. The band gates itself on detail.isExpanded — a slot is a place, not a state, so the template decides what to draw and when. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  enableRowExpansion: true,
  getRowId: row => row.id,        // ⚠️ mandatory — throws in dev without it
{{ "}" }});
<nge-table [config]="config" [state]="state()" (stateChange)="state.set($event)">
  <ng-template ngeTableSlot="row-detail" [ngeTableSlotOf]="rows" let-detail>
    @if (detail.isExpanded) {{ "{" }}
      <div>{{ "{" }}{{ "{" }} detail.row.name {{ "}" }}{{ "}" }}</div>
    {{ "}" }}
  </ng-template>
</nge-table>
@if (detail.isExpanded) {
{{ detail.row.name }} owner: {{ detail.row.owner.name }}
}

2. Only some rows open

enableRowExpansion also takes a predicate. It receives the row datum, never an engine row, so writing one never needs a @tanstack/* import. Rows it rejects render their chevron disabled rather than absent — a control that vanishes reads as a bug, where a disabled one reads as a rule. 

enableRowExpansion: row => row.quantity > 250,
@if (detail.isExpanded) {
{{ detail.row.name }} quantity: {{ detail.row.quantity }}
}

3. A band inside a virtualized table

rowDetailHeight is what lets expansion compose with a window. A virtualized row is positioned from sizes the virtualizer was given rather than laid out, so an expanded row is sized rowHeight + rowDetailHeight and the rows beneath it move down by that much. Declared rather than measured, because a size has to be computable before the row is rendered.

The cost is a number you keep true: content taller than the declared height scrolls inside the band while virtualization is on, and grows past it while virtualization is off — where nothing is positioned by arithmetic, so nothing can be overlapped. 

config = createNgeTableConfig<Row>({{ "{" }}
  columns: NGE_TABLE_FIXTURE_COLUMNS,
  data: rows,
  enableRowExpansion: true,
  enableVirtualization: true,
  getRowId: row => row.id,
  rowDetailHeight: 150,           // the band's height, in pixels
{{ "}" }});
@if (detail.isExpanded) {
{{ detail.row.name }} owner: {{ detail.row.owner.name }} quantity: {{ detail.row.quantity }}
}

4. Restoring a saved view

Which rows a user opened is part of the view they would expect a saved layout to bring back, so it lives in the persistable state rather than beside it. Hand state.expanded in with the sort and the table opens on both.

⚠️ Host-driven state is silent — it emits no NgeTableEvent. Restoring a layout must not replay as user activity in a consumer's log. 

state = signal(createNgeTableState({{ "{" }}
  expanded: {{ "{" }} 'row-2': true {{ "}" }},
  sorting: [{{ "{" }} desc: false, id: 'name' {{ "}" }}],
{{ "}" }}));
@if (detail.isExpanded) {
{{ detail.row.name }} restored from a saved view, not clicked
}

5. Reading the state

⚠️ state.expanded is Record<string, boolean> | true. The true shorthand is what expand-all writes, so a reader that narrows the slice to a Record is wrong for exactly the gesture most likely to produce a large payload. The compiler catches the narrowing; it cannot catch a cast. 

const isOpen = (expanded: NgeTableExpanded, rowId: string): boolean =>
  expanded === true || expanded[rowId] === true;

The same shape arrives on the event stream as {{ "{" }} kind: 'expansion-change', expanded {{ "}" }}. 

onTableEvent(event: NgeTableEvent<Row>): void {{ "{" }}
  if (event.kind === 'expansion-change') {{ "{" }}
    this.persist(event.expanded);
  {{ "}" }}
{{ "}" }}

6. A domain's own disclosure control

Project expand-cell — and expand-header for expand-all — and the native chevron steps aside. The context carries isExpanded, canExpand and a toggle callback, so a projected control inherits the capability check without knowing it exists.

⚠️ A projected control sits inside a row whose click may select, so it owes itself a $event.stopPropagation() exactly as the native one does. 

<ng-template ngeTableSlot="expand-cell" [ngeTableSlotOf]="rows" let-expand>
  <dlc-button
    [disabled]="!expand.canExpand"
    (click)="$event.stopPropagation(); expand.toggle()"
  />
</ng-template>
@if (detail.isExpanded) {
{{ detail.row.name }}
}

7. What this is not

⚠️ This is a detail band, not tree data. TanStack's getExpandedRowModel() exists to flatten sub-rows into the visible row model; a band needs none of it, only getRowCanExpand and row.getIsExpanded(). Hierarchical rows bring getSubRows, row.depth, indentation and grouping with them, and are their own story.

Also not here, deliberately: animating the band open, and loading its content lazily on first expand. Both are a consumer's to add inside the template they already own.
