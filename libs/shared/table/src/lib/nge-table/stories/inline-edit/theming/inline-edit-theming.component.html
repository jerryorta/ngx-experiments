NgeTable — Inline Editing (Theming)

An activated cell has no theme vocabulary of its own, and in this story it should not: ARCH-292 ships no editor, so a --nge-table-editor-* namespace declared here would sit inert across all six persona themes — the mistake ARCH-277 had to undo and ARCH-286 had to finish. The controls below read what the table already publishes: --nge-table-surface, --nge-table-border-color, --nge-table-focus-ring-color and --nge-table-focus-ring-width. ARCH-293 introduces the editor tokens together with the editors that consume them.

⚠️ Click a cell in each section. Activation is the default, so an editable table at rest looks exactly like a read-only one — there is nothing to review until an editor is open.

Every section below is a scoped wrapper class re-declaring tokens. There is no config.theme; this is the whole theming surface, and it is what a consuming app writes.

1. Library defaults

No overrides at all. The input takes the table's own surface and border, and its focus ring is the same one a sortable header shows — so an editable table looks like the table it is part of before anyone themes anything.

⚠️ The ring is inset. .nge-table__cell carries overflow: hidden — an ARCH-243 decision that stays, because a cell's content is arbitrary and must not spill — so an outer ring is clipped on whichever edge meets the cell wall.

2. A branded ring and surface

Three declarations move the editor: the focus ring, the surface it sits on, and the border it carries. Nothing in the section names an editor — the control inherits because it reads the table's tokens rather than tokens of its own. 

.branded {{ "{" }}
  --nge-table-focus-ring-color: #7c3aed;
  --nge-table-focus-ring-width: 3px;
  --nge-table-surface: #faf5ff;
  --nge-table-border-color: #ddd6fe;
{{ "}" }}

3. Dark

The whole dark treatment, and no editor-specific line in it. An input on a dark surface needs the surface and the text colour to move together, which they do because both are the table's own tokens — the property that makes "the editor follows the theme" true rather than a thing each app re-derives.

4. Compact rows

A shorter row and tighter padding. ⚠️ Watch the input, not the text: a control that set its own height would break out of a shortened row, and the reason this one does not is that it takes its box from the cell rather than declaring one. 

.compact {{ "{" }}
  --nge-table-row-height: 30px;
  --nge-table-cell-padding-x: 8px;
  --nge-table-font-size: 12px;
{{ "}" }}

⚠️ This section passes themableGeometry, and without it the wrapper below would do nothing at all. createNgeTableConfig resolves rowHeight and headerHeight unconditionally, and <nge-table> writes the resolved numbers as inline custom properties on its host — which outrank a class regardless of specificity. A theming section built on the factory renders at the library default no matter what the class declares, and fails silently. Omitting the two fields is what hands the say back to the theme.

5. An always-live column, themed

The slider is the one control on this page visible without a gesture, which makes it the one place a theme change can be judged at a glance. It reads the same focus-ring token for its fill and its thumb, so a brand colour moves the whole control rather than one part of it.
