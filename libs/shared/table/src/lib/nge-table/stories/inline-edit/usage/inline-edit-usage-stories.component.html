NgeTable — Inline Editing (Usage)

Two lines of integration, and one obligation. The column opts in with a namespaced meta key; the cell branches on cell.isEditing() and renders whatever control you want. Then — because the library owns no data — you apply the change.

1. Switching a column on

ngeEdit is a namespaced meta key, beside ngeExport (ARCH-248) and ngeFill (ARCH-271). ColumnMeta is a single globally-merged interface shared by every addon and every domain in the workspace, so a bare editable field would be claimed by whoever declared it first. 

const columns: NgeTableColumn<Row>[] = [
  {{ "{" }} accessorKey: 'name', header: 'Name', id: 'name',
    meta: {{ "{" }} ngeEdit: {{ "{" }} enabled: true {{ "}" }} {{ "}" }} {{ "}" }},
];

⚠️ config.getRowId stops being optional. An edit is keyed by rowId + columnId, so without one the engine keys rows by array index and a sort would land the patch on a different record. The library throws in dev rather than degrade — the same call ARCH-268 made for row selection.

2. The cell template, and the four members it is handed

NgeCellContext carries isEditing(), beginEdit(), commitEdit(value) and cancelEdit(). They are callbacks on the context rather than a service to inject, for the reason NgeSelectionCellContext.toggle is (ARCH-278): a projected ng-template resolves DI from its own declaration injector — yours — and can never reach the table. 

<ng-template ngeCell="name" [ngeCellOf]="rows" let-cell>
  @if (cell.isEditing()) {{ "{" }}
    <input #field [value]="cell.row.name"
           (blur)="commit(cell, field.value)"
           (keydown.enter)="field.blur()"
           (click)="$event.stopPropagation()" />
  {{ "}" }} @else {{ "{" }}
    {{ "{{" }} cell.row.name {{ "}}" }}
  {{ "}" }}
</ng-template>

commit(cell: NgeCellContext<Row>, value: string): void {{ "{" }}
  if (cell.isEditing()) {{ "{" }} cell.commitEdit(value); {{ "}" }}
{{ "}" }}

⚠️ The isEditing() guard is load-bearing, not defensive filler. Removing a focused element from the DOM fires a native blur on it, and esc does exactly that — it clears the edit, which flips isEditing() false and tears this very <input> down. Without the guard, that teardown-triggered blur commits the draft esc was meant to discard, so cancelling silently means saving.

enter routes through blur() rather than committing directly, so there is one commit path instead of two that can both fire. And read cell.row.<field> rather than cell.value: the latter is unknown, because a cell's value type depends on which column it belongs to and the column id is a string — row is typed.

⚠️ isEditing is a signal, not a boolean. Cell contexts are memoised against the engine cell — deliberately, because that memo is what keeps ten thousand rows affordable — so a plain field would be read once at first build and served stale forever. The cell would render, the read-only text would stay, and activation would simply never appear.

⚠️ A control inside a cell owes itself $event.stopPropagation() on its click, the same arrangement the resize grip (ARCH-244), the header slots (ARCH-246) and the select-all checkbox (ARCH-268) already use. Without it a click inside the control also reads as a click on the cell and the row.

3. The obligation — applying the intent

Committing emits edit-intent. It carries the same NgeCellPatch fill-intent does, so one handler serves both: 

onEvent(event: NgeTableEvent<Row>): void {{ "{" }}
  if (event.kind !== 'edit-intent' && event.kind !== 'fill-intent') return;
  this.rows.update(rows => applyPatches(rows, event.cells));   // your write
{{ "}" }}

The kinds stay distinct so a host may accept a fill and reject a hand-typed edit, or the reverse. Each patch carries previousValue as well as value, which is what makes undo yours to implement in one more line — the same walk, reading the other field. Try the button below.

4. Always-live, for the column that wants it

Activation is the default because thirty visible rows across three editable columns would otherwise be ninety control instances nobody asked for. meta.ngeEdit.alwaysLive opts one column out of that saving, for the case where the control is the reading — a value scanned down a column rather than opened a cell at a time. 

meta: {{ "{" }} ngeEdit: {{ "{" }} enabled: true, alwaysLive: true {{ "}" }} {{ "}" }}

⚠️ Per column, never table-wide. Every other column keeps paying exactly what activation exists to avoid.

The slider below is a composed div carrying role="slider" — which is also what makes the table leave its drag alone. Any control declaring a widget role, or carrying data-nge-interactive, is recognised; the library never names your components.

5. What this story does not ship

No editor components. The controls above are the demo's own, which is what a consumer writes today. ARCH-293 adds the library's own input and checkbox, and ARCH-294 a select over a CDK overlay — and a projected [ngeCell] template will still win over them, the same resolution order ARCH-278 fixed for the selection control.

Export's formatted staying in step with what an editable cell renders remains yours: the library sees a template on one side and a format function on the other, and cannot compare them.
