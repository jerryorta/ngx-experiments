NgeTable — Row-Detail Content (Interaction)

A row-detail band is the only surface in the table as wide as the table itself, which is what lets it hold content a cell cannot. Below, one band carries two independent charts side by side — a crosshair trend and a lag cloud, both built from the same twelve numbers on the row. Expand a row to see them.

Drag rowDetailHeight in the Controls panel. Both charts follow it, because neither carries a height of its own — the band declares one and the content claims it by reading --nge-table-row-detail-height. That single CSS rule is this story's subject; everything else is the two charts being ordinary charts.

1. Two charts in a band, over a windowed table

10,000 rows with virtualization on — the regime where the band's height is arithmetic rather than decoration. The virtualizer was told an expanded row is rowHeight + rowDetailHeight tall and placed every row beneath it on that basis, so the band takes a fixed height and scrolls anything past it. Open a row, then scroll: the rows below stay exactly where the window put them.

Move the pointer across the left chart — the dashed guide snaps to the nearest day and the shared card lists all three series at that x. Hover a point on the right chart for its own tooltip, and click a legend entry to isolate a lag. Two charts, two independent interaction surfaces, one band.

2. The state, which is what the contract actually moves

Expansion is an ordinary slice of NgeTableState — id-keyed, JSON-serialisable, and persistable like the rest of a user's view. A band full of charts changes nothing about that: the charts are markup the slice decides whether to render.

state.expanded — {{ windowedOpenCount() }} open 
{{ windowedExpandedJson() }}

Writing the slice from OUTSIDE the table proves the other half of the round trip, which a click on the chevron never shows. Host-pushed state is deliberately silent — it emits no NgeTableEvent.

The third one opens a row the window has not rendered. Scroll down to it — the band is already open when it arrives, because the state named the row rather than the element.

3. The same band, un-windowed

Six rows, virtualization off. The band takes the token as a definite height here too, and content past it scrolls exactly as it does in a window — the two regimes agree, which is what let the open be animated (a transition needs two definite endpoints). The band markup is character-for-character the same; only the table's config differs. That is what makes the height rule below portable rather than a fix for one mode.
