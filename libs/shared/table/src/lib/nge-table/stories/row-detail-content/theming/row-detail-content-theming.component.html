NgeTable — Row-Detail Content (Theming)

There is no config.theme on NgeTableConfig, so the substance of this story is its SCSS. Each section is a scoped wrapper class re-declaring tokens — exactly what a consumer overriding them would write.

A band is the one surface in the table where a second token family turns up: the band is the table's, the chart on it is the charts library's, and a theme that moves only one of them is visible from across the room.

1. The band's own surface

--nge-table-row-detail-surface paints the band behind whatever the consumer projects into it. It is the band's only colour token — everything else you can see below belongs either to the story's markup or to the chart. 

.theme-parchment {{ "{" }}
  --nge-table-row-detail-surface: #fdf6e3;
{{ "}" }}

2. Two token contracts meet in the band — and both have to be told

The chart inside the band reads --nge-chart-* and knows nothing about the table. Below are the same band and the same chart under two wrapper classes: on the left the chart family sits at the charts library's own light defaults, on the right it is bridged to match. The left is what a half-finished bridge looks like — a dark band with a bright white panel punched through it.

⚠️ The left block writes those light values out rather than omitting the family, and it has to: Storybook bridges --nge-chart-* globally for its theme toolbar, so a wrapper that simply left them out would inherit the toolbar's dark values and both tables would look themed. The literals are exactly the fallbacks nge-chart's own SCSS declares — so this is what an application that bridged --nge-table-* and stopped really renders. 

/* ❌ Table bridged, charts left at their own defaults. */
.theme-half {{ "{" }}
  --nge-table-surface: #16161a;
  --nge-table-row-detail-surface: #1d1d24;
  --nge-table-on-surface: #e8e8ed;

  --nge-chart-surface: #ffffff;          /* the charts library's literal default */
  --nge-chart-on-surface: #1d1b20;
  --nge-chart-outline-variant: #e0e0e0;
{{ "}" }}

Neither library is at fault here and neither should reach into the other: a band is a place where a consumer's markup lives, and a consumer theming that markup owns both ends of it. ARCH-277 bridges --nge-table-* across every domain theme; a domain that also renders charts in bands bridges --nge-chart-* in the same file.

3. The band's height is a config concern — until the config declines it

⚠️ createNgeTableConfig() fills rowDetailHeight in from NGE_TABLE_DEFAULTS unconditionally, and <nge-table> then publishes it as an inline custom property on the host — where it beats a wrapper class outright, because an inline declaration outranks a class selector regardless of specificity. So a theme cannot move the band height of a factory-built table, and that is deliberate: a virtualized row is positioned as rowHeight + rowDetailHeight, so a theme moving the band alone would not restyle the table, it would put the band and the row beneath it in disagreement about where the row ends.

Hand-author the config and omit the field, and the token is the theme's again. Both tables below share that one config; only the wrapper class differs — and because the band's content reads --nge-table-row-detail-height rather than a number, the charts follow. 

// `rowDetailHeight` deliberately absent — the factory would fill it in.
themableHeightConfig: NgeTableConfig<Row> = {{ "{" }}
  columns, data, enableRowExpansion: true, getRowId: row => row.id,
{{ "}" }};
.theme-short {{ "{" }} --nge-table-row-detail-height: 170px; {{ "}" }}
.theme-tall  {{ "{" }} --nge-table-row-detail-height: 340px; {{ "}" }}
170px
@if (detail.isExpanded) {
{{ detail.row.name }} — trend over 12 days
}
340px
@if (detail.isExpanded) {
{{ detail.row.name }} — trend over 12 days
}

⚠️ This only holds off virtualization. Switch the window on and the component pins the resolved height inline again whether the config named one or not, because the arithmetic that places every row beneath needs the number in TypeScript.

5. What a band's theme can and cannot reach

The four tiers, as they apply to a band:

Tier Tokens Themeable from a wrapper class?
Read from CSS --nge-table-row-detail-surface Yes
Another library's contract --nge-chart-*, on whatever the band holds Yes — and it is on you to, as Section 2 shows
Overwritten inline by the component --nge-table-row-detail-height Only when the config omits it, and only off virtualization
Never yours to set the --nge-table-internal-* family No — runtime lane geometry
