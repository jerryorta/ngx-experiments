Pie Chart - Usage Examples

Practical examples for the pie / donut / semi-circle layer. One radial primitive fans out across three shapes via config: a full pie (innerRadius: 0), a donut (innerRadius as a ratio 0–1 carves the center hole), and a semi-circle / gauge (startAngle / endAngle sweep in radians). Each datum's value maps to a proportional arc.

1. Basic Pie

Simplest way to create a pie chart using createPieChartConfig(). Provide an array of {{ "{" }} label, value {{ "}" }} data points — one slice per point, in input order. 

data: NgePieDataPoint[] = [
  {{ "{" }} label: 'Rent', value: 1800 {{ "}" }},
  {{ "{" }} label: 'Food', value: 600 {{ "}" }},
  {{ "{" }} label: 'Transit', value: 300 {{ "}" }},
  {{ "{" }} label: 'Utilities', value: 250 {{ "}" }},
  {{ "{" }} label: 'Savings', value: 450 {{ "}" }},
];

config = createPieChartConfig({{ "{" }} data: this.data {{ "}" }});

<nge-chart [config]="config" />

2. Donut

innerRadius is a ratio (0–1) of the self-computed outer radius, not pixels — so it stays resize-safe. 0.6 carves a center hole 60% of the radius. 

config = createPieChartConfig({{ "{" }}
  data: this.data,
  innerRadius: 0.6, // donut
{{ "}" }});

3. Semi-circle Donut (Gauge)

startAngle and endAngle are in radians. Sweeping less than a full turn produces a semi-circle / gauge. Here -π/2 → π/2 draws the top half. 

config = createPieChartConfig({{ "{" }}
  data: this.data,
  innerRadius: 0.5,
  startAngle: -Math.PI / 2,
  endAngle: Math.PI / 2,
{{ "}" }});

4. Custom Slice Colors

Pass a seriesColors palette — slice input index maps to colors[index % length]. A per-datum color on any data point wins over the palette for that one slice. 

config = createPieChartConfig({{ "{" }}
  data: this.data,
  seriesColors: ['#1E88E5', '#43A047', '#FB8C00', '#8E24AA', '#00ACC1'],
{{ "}" }});

// Or override a single slice on the datum:
// {{ "{" }} label: 'Savings', value: 450, color: '#00ACC1' {{ "}" }}

5. On-arc Labels

showLabels: true draws each slice's label at its arc centroid, styled from theme.pie.label. Labels are opt-in, so existing pies keep their current look, and they never intercept the pointer — hover and click still reach the slice underneath. 

config = createPieChartConfig({{ "{" }}
  data: this.data,
  innerRadius: 0.5,
  showLabels: true,
{{ "}" }});

6. Custom Label Text

formatLabel replaces the default label text with anything derived from the datum — a share of the total, a currency amount, an abbreviation. It defaults to the datum's own label. 

const total = this.data.reduce((sum, point) => sum + point.value, 0);

config = createPieChartConfig({{ "{" }}
  data: this.data,
  innerRadius: 0.5,
  showLabels: true,
  formatLabel: (d) => `${{ "{" }}Math.round((d.value / total) * 100){{ "}" }}%`,
{{ "}" }});

7. The Small-slice Rule (minLabelAngle)

A wedge can be narrower than the label naming it. Slices sweeping less than minLabelAngle radians are left unlabelled rather than drawn with text spilling across their neighbours — the default is 0.15 rad (≈ 8.6°, about 2.4% of a full turn). Below, Fees is under 1% of the total: it disappears from the labels on the left and returns on the right once the threshold is lowered. A slice regains its label automatically as soon as the data widens it.

Default (0.15 rad) — Fees unlabelled
minLabelAngle: 0.02 — Fees labelled
config = createPieChartConfig({{ "{" }}
  data: this.data, // includes a sub-1% 'Fees' slice
  showLabels: true,
  minLabelAngle: 0.02, // radians — lower the bar to label thin wedges
{{ "}" }});

8. Outside Labels (labelPosition: 'outside')

On-arc labels stop working once the categories outnumber the room: at 30 slices not one wedge is wide enough to hold its own name, so the minLabelAngle rule above drops every single label. labelPosition: 'outside' moves them beyond the arc instead — two columns, left and right of the pie, with every label outside (never a mix, which would read as inconsistent and put some text back on a saturated fill).

Three things make it work. labelGutter reserves width on each side and the pie's radius shrinks to fit, because the layers group is clipped to the plot area — a label drawn past it would be cut off. Labels are then pushed apart to labelLineHeight so none overlap. Finally, a label the collision pass had to move gets a leader line back to its slice; one that landed at its natural height gets none, which is why the leaders cluster where the chart is crowded. Outside mode also drops minLabelAngle's default to 0 — the wedge no longer has to contain the text, so a 36-of-3000 sliver labels perfectly well.

labelPosition: 'outside' — all 30 labelled, none overlapping
The same data on the default on-arc placement — 0 labels survive
config = createPieChartConfig({{ "{" }}
  data: this.goldMedalData, // 30 countries, 932 down to 36
  showLabels: true,
  labelPosition: 'outside',
  labelGutter: 130,     // px reserved on EACH side (default 96)
  // labelLineHeight: 14,  // minimum gap between adjacent labels
{{ "}" }});

Per-datum labelColor still wins in outside mode — China above is the highlight-one-entry idiom. Outside labels read theme.pie.labelOutside, which tracks --nge-chart-on-surface; on-arc labels keep their own theme.pie.label black / white contrast pair, because those sit on a slice fill rather than on the page.

Donut with outside labels
leaderLines — who gets a connector

The default 'displaced' draws a leader only where collision resolution had to move a label, so the lines appear exactly where the eye needs help tracing a label back to a thin wedge — and nowhere else. 'all' instead treats the connector as part of the chart's grammar: every label gets one, and an uncrowded label takes a short, straight radial tick rather than an elbow. 'none' leaves the columns to stand alone. The geometry is identical in all three — only which labels earn a line changes. 

config = createPieChartConfig({{ "{" }}
  data: this.goldMedalData,
  showLabels: true,
  labelPosition: 'outside',
  leaderLines: 'all',   // 'displaced' (default) | 'all' | 'none'
{{ "}" }});
leaderLines: 'none'
labelLayout — where an uncrowded label rests

'perimeter' (the default) keeps each label on a ring just past the arc at its own mid-angle, so the ring follows the pie's curve and steps in and out rather than running down a ruler. A label the collision pass never touched sits exactly where its wedge points. 'columns' instead stacks each hemisphere onto a straight vertical line at a fixed x — every label is pulled off its slice's own bearing even when nothing was going to collide. Collision separation is identical in both — a crowded label still gets pushed clear, it just slides along the ring instead of collapsing into the column.

The ring does not draw fewer connectors. 'displaced' means "the collision pass moved this label vertically", and the y-pass that decides it is shared by both layouts — so leaderLines: 'displaced' emits the same count either way (12 and 12 on the 30 countries below; 0 and 0 at five slices). What changes is length: a ring connector ends on its own slice's bearing instead of reaching across to a ruler line. Charted with leaderLines: 'all' on the 30 countries, the ring's mean leader is 45px against the column's 185px — 1341px of ink against 5556px.

Reach for 'columns' at the ring's density ceiling: leaders stay completely untangled up to about 20 categories and cross sharply past it, because the labels can no longer fit near their own bearings and the connectors dragged behind them sweep over their neighbours. A column terminates every leader at the same x, so y-order alone keeps them nested however dense the pie gets — the reason both layouts are still worth having.

The connector changed with it: a leader now runs arc edge → the same mid-angle carried out to the label ring → the label, so the segment leaving the slice is radial and visibly belongs to the wedge it names, instead of reading as one long diagonal across the chart.

labelLayout: 'columns' — two ruler lines
labelLayout: 'perimeter' — the ring follows the curve
config = createPieChartConfig({{ "{" }}
  data: this.goldMedalData,
  showLabels: true,
  labelPosition: 'outside',
  labelLayout: 'perimeter',   // 'perimeter' (default) | 'columns'
{{ "}" }});

The gutter has to clear the ring at its widest — 3 and 9 o'clock — so the layout is worth checking at several category counts. All three below run the default labelGutter of 96px. At 5 nothing collides and no leader is drawn at all; by 20 the crowded arc has earned a few.

9. Tooltip on Hover

Enable tooltips with tooltip: {{ "{" }} enabled: true {{ "}" }}. The default formatter shows the slice label and raw value; hover a slice to see it. 

config = createPieChartConfig({{ "{" }}
  data: this.data,
  innerRadius: 0.5,
  tooltip: {{ "{" }} enabled: true {{ "}" }},
{{ "}" }});

10. Click Handling

Provide an onClick callback in the config. The event carries the full data point for the clicked slice. 

config = createPieChartConfig({{ "{" }}
  data: this.data,
  onClick: (event) => {{ "{" }}
    console.log('Clicked:', event.data.label, event.data.value);
  {{ "}" }},
{{ "}" }});

11. With a Legend

The pie layer is inherently categorical — pair it with extractPieChartLegendItems(data) to build a legend whose swatches match the slices exactly. Combined here with a computed signal config so the legend + slices rebuild together when the data changes. 

legendConfig = computed(() => ({{ "{" }}
  ...createPieChartConfig({{ "{" }} data: this.data(), innerRadius: 0.55 {{ "}" }}),
  legend: {{ "{" }}
    enabled: true,
    items: extractPieChartLegendItems(this.data()),
    position: 'right',
    swatchShape: 'square',
  {{ "}" }},
{{ "}" }}));

<nge-chart [config]="legendConfig()" />
