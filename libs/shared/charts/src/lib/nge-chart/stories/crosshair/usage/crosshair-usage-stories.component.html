Crosshair — Usage

The shared crosshair snaps a dashed vertical guide to the nearest datum x, marks each series with a focus dot, and — with shared: true — shows ONE tooltip listing every series' value at that x. The shared tooltip is a real Angular tooltip: the chart runs [chromelessTooltip]="true" and each <nge-chart> projects a #ngeChartTooltip template that renders the card from content.rows (a swatch row.color, row.label, and row.value per series). Move the pointer across a plot to try it.

1. Line host — multi-series

Three series on a LINE host. Enable the crosshair on the chart's base.crosshair, then render the shared card from content.rows in a chromeless #ngeChartTooltip template. 

const cfg = createLineChartConfig({{ "{" }} data, seriesColors {{ "}" }});
cfg.base.crosshair = {{ "{" }} x: true, shared: true {{ "}" }};

<nge-chart [config]="cfg" [chromelessTooltip]="true">
  <ng-template #ngeChartTooltip let-content>
    <!-- header = content.label, one row per content.rows entry -->
  </ng-template>
</nge-chart>
{{ content?.label }}
@for (row of rowsOf(content); track row.label) {
{{ row.label }} {{ row.value }}
}

2. Area host — multi-series

The SAME crosshair over an AREA host (overlaid fills with a top stroke). The engine-level crosshair sources its rows from any line/area layer, so nothing about the tooltip wiring changes between host types.

{{ content?.label }}
@for (row of rowsOf(content); track row.label) {
{{ row.label }} {{ row.value }}
}

3. Single series

With one series the shared tooltip degrades gracefully to a single row (labelled Value when the data carries no seriesId). The guide + focus dot behave exactly as in the multi-series case.

{{ content?.label }}
@for (row of rowsOf(content); track row.label) {
{{ row.label }} {{ row.value }}
}

4. Snapping — 'datum' vs 'tick'

Both charts below share the SAME data on a continuous numeric x, observed every 7 days, with gridlines at xAxisTicks: 10 — so the observations never coincide with the round tick values d3 picks. With snap: 'datum' the guide lands on a data point, between gridlines. With snap: 'tick' it locks onto a gridline instead, using the same tick geometry the axis is drawn from. The focus dots and tooltip keep describing the nearest real datum either way, so the dots stay on the series and the tooltip header names the datum's x — never the tick's. On a categorical x (examples 1–3) every tick already sits on a node, so the two modes are identical. 

cfg.base.crosshair = {{ "{" }} x: true, shared: true, snap: 'tick' {{ "}" }};
snap: 'datum'
{{ content?.label }}
@for (row of rowsOf(content); track row.label) {
{{ row.label }} {{ row.value }}
}
snap: 'tick'
{{ content?.label }}
@for (row of rowsOf(content); track row.label) {
{{ row.label }} {{ row.value }}
}

5. Scatter host — nearest point in 2-D

Scatter y is not a function of x, so "the value at this x" is not a well-formed question — the meaningful anchor is the nearest point. A scatter host therefore resolves the anchor in 2-D with Delaunay.find(), the same triangulation the scatter layer builds for its own hit-test overlay, and the guide lands on that point. Move vertically at a fixed x and the crosshair re-anchors onto whichever series' point is genuinely closest — something the line/area hosts' x-only snap cannot do. snap: 'tick' is inert here: a tick is an x, and this anchor is a point. 

const cfg = createScatterChartConfig({{ "{" }}
  data,
  // the layer's own Voronoi tooltip writes to the SAME host as the
  // crosshair — leave both on and they fight over the card
  tooltip: {{ "{" }} enabled: false {{ "}" }},
{{ "}" }});
cfg.base.crosshair = {{ "{" }} x: true, shared: true {{ "}" }};
{{ content?.label }}
@for (row of rowsOf(content); track row.label) {
{{ row.label }} {{ row.value }}
}
Both guides on the point
